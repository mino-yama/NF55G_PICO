### 個別記録の共通項目

- 記録ID、日時・タイムゾーン、実施者、要求・Issue・試験ID。
- 治具識別、回路・基板版、配線・電源、NF55G識別とFW、SD、QR、測定器の識別と設定。
- 配置ソース・FW・設定のhash、commit、未コミット差分、使用ツールと版。commitだけで配置版を説明できない場合はファイル別台帳を付ける。
- 手順、入力、期待値と根拠、試験回数・時間・要求間隔、実測値、合否と判定者。
- ATE送受信、NF55G RAW、CSV、解析、写真・波形等の原本へのリンク。
- 原因の確認根拠、修正内容、対策後・回帰確認、影響範囲、残Issue。過去記録は当時の状態として保持する。

## 5. 信頼性確認で扱う項目

以下は検証項目の候補であり、実施済み一覧ではない。

| 観点 | 確認する内容 |
|---|---|
| 通信の正確性 | 正常・境界値・不正フレーム、BCC、timeout、Retry、遅延・重複応答、切断・再起動、単一Transaction |
| データの正確性 | Decode・単位・ビット、Cache失効、試行分離、古い測定値・QR・応答の不採用、ATEへの返却一致 |
| 処理能力と継続運転 | 合意した量産要求間隔・コマンド構成、最大待ち時間、連続試験、Queue上限、SD負荷・容量、ログ破棄 |
| 異常検出と復帰 | SDなし・書込失敗、通信断、時計異常、電源断・復帰。検出可能な異常、失われ得るデータ、再試験手順 |
| 測定の信頼性 | 7355とシャント等の識別・校正情報、レンジ・測定条件、換算、分解能・不確かさ、基準との比較。測定経路変更後の確認 |
| ハードウェア適合 | 最終回路と現物の一致、電源余裕・給電経路、信号レベル、誤接続対策、実使用環境の条件 |
| 変更後の維持 | 変更影響評価、回帰試験、版の識別、治具複製時の同等性、保守・交換後の点検 |

リスク評価では、例として旧値を使う誤判定、誤補正、試行ログ混在、ログ喪失、通信停止を扱う。重要度・許容水準を独断で決めず、対策とその試験根拠を対応付ける。測定信頼性の資料はATE側の判定条件・測定系資料とも整合させる。

## 6. 証跡の保全と顧客向け資料

- 原本は変更せず、解析・注記・顧客提出版は別ファイルとする。顧客提出資料には内部原本の参照IDと対象版を付ける。
- 正式証跡は案件内の版管理・バックアップ対象として保管する。temp、コンソール履歴、RAM履歴だけを唯一の保存先にしない。
- 一時保存しかない既存証跡は、参照先の存在・原本との照合可否を確認して正式保管へコピーし、hashと出所を残す。欠落時に結果を再現・補作した原本として扱わない。
- SHA-256は内容の同一性確認に使う。試験内容の妥当性や実施日時・実施者の証明をhashだけで済ませない。バックアップ先・保存期間・アクセス権・確認者は運用として決める。
- 最終リリース時に要件・設計・試験・実機配置の組合せを固定し、受入確認を記録する。Git履歴は記録の一部であり、実機版・試験原本との対応も保持する。
- 顧客提出用には、適用範囲、最終構成、要件対応表、検証条件と結果、残る制約、運用・保守条件をまとめる。原典やソースの提出範囲は顧客要求・機密性・再配布条件に合わせる。

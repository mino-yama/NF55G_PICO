# RTC異常時の仮IDログ保存 改善資料

Date: 2026-11-27  
Revision: Rev.0  
状態：改善方針の整理。実装・Pico配置は行わない。

## 1. 目的と今回の指定

RTCがない場合、または日時を取得できない場合にも、仮IDを使ってSDへのログ記録を開始できるようにする。試験中にシリアルNo.を取得できれば、試験終了時にシリアルNo.を含む名前へ変更する。

電源OFF後の再起動で仮IDを初期値へ戻すと、既存ファイルと重複する。ユーザー指定により、SD内の既存ログを確認し、使用済み番号の最大値＋1を採番する方向で改善する。シリアルNo.付きへ変更した後も仮IDを残す。作成時の同名確認と上書き禁止を維持し、SDを確認できない場合は未使用と推測して採番しない。

案件フォルダは現在のNF55G_Picoを継続する。本書は今後の改善資料であり、現在のPicoが仮IDログへ対応済みであることを意味しない。

詳細は[RTCなしでの不具合確認結果](RTC_Missing_Logger_Review_20261127_Rev0.md)と[Host再現結果](../tmp/check_rtc_missing_logger_20261127_result.json)を参照する。

| 対象 | 現行処理と確認結果 |
|---|---|

| FileSDSink._log_name() | 日時名と試行番号・S/N付き日時名を受理するが、上記のRTCなし名を受理しない。 |
| TEST_START | LoggerはFILENAMEで記録開始に失敗する。ただし試験期間は開始し、ATEへは受付のOKを返す。 |
| LOG_CONT_START | ERR:FILENAMEとなり、SDファイルを開けない。 |
| 起動時のRTC初期化 | ValueError／OSError時はrtc=Noneとして継続する。 |
| 試行番号の引継ぎ | 両BANKの認識対象ログから`_T`番号の最大値を取得し、TEST_START時に最大値＋1を使う処理が既にある。RTCなし名・CONTの仮IDへの拡張は未実装。 |
| シリアルNo.付きへの変更 | 同試行で取得した6桁シリアルNo.を、試験終了時のflush・close後に開始時の名前へ付加する処理が既にある。変更先が存在する場合は上書きしない。 |

## 3. 改善後の処理の流れ

1. ログ開始に先立ち、所有マーカー・使用中BANK情報・両BANKの一覧確認を正常に完了する。
2. RTC日時が正常に取得できれば、既存の日時名を使う。RTCなし・読取り失敗・無効日時なら仮ID名を選ぶ。無効日時の詳細な判定条件は実装前に整理する。
3. 認識対象ログから使用済み番号の最大値を求め、実行中に確保済みの番号も考慮して次の番号を採番する。電源投入のたびに無条件で初期値から採番しない。
4. 作成前に両BANKでの番号使用と保存先の同名ファイルを確認する。衝突なら次の候補へ進め、既存ファイルを上書きしない。確認I/Oの異常を「存在しない」と読み替えない。
5. 記録中は開始時に決めた名前を維持する。RTCが途中で復帰しても、開いたファイルを日時名へ付け替えない。
6. TESTでは同試行のシリアルNo.を取得できた場合、終了時のflush・close後に「シリアルNo.＋開始時の名前」へ変更する。取得できなければ仮ID名のまま保存する。
7. 新しいファイルを作る次の記録では、その時点のRTC状態を改めて確認する。CONTのロールオーバーも共通の命名・採番経路を使用する。

仮IDは時刻ではない。架空の日時をRTC正常値としてログに記録しない。RTC状態と採用した識別子を識別できる記録方法は、詳細設計で定める。

## 4. 命名と採番の案

以下は読みやすさと既存試行番号の利用を考慮した案であり、正式な命名書式・番号共用方法の確定ではない。

| 記録 | 仮ID名の例 | シリアルNo.取得後の例 |
|---|---|---|
| TEST | `NO_RTC_T000123.csv` | `000001_NO_RTC_T000123.csv` |
| CONT | `NO_RTC_C000124.csv` | 原則は開始名のまま。製品との対応付けは別途確認。 |

番号は例であり、固定送信値や実在する製品のシリアルNo.ではない。シリアルNo.は文字列として先頭ゼロを保持する。

改善案では、既存の日時名付きTEST番号、シリアルNo.付きTEST番号、新しい仮ID名の番号を両BANKから読み取る。TEST／CONTで共通の最大番号を引き継ぐ方式を候補とする。番号に欠番が生じても再利用のために詰め直さない。桁あふれ時に先頭へ戻さず、扱いを明示する。

正式書式を決める際は、既存のtrial_idとの対応、ATEからの追跡、桁数上限を確認する。日時付きCONTの従来形式と、既存ログの互換性は維持する。

## 5. 電源断・再起動時の重複防止

| 状況 | 改善後に必要な扱い |
|---|---|
| 再起動時もRTCエラー | 両BANKの既存番号から再採番し、初期値へ無条件に戻さない。 |
| 前回ログは反対側BANKにある | 使用中BANKだけを見ず、両BANKの番号を確認する。 |
| 前回名はシリアルNo.付きへ変更済み | 接頭辞を正しく解析し、残っている仮IDも採番対象にする。 |
| 作成直後の電源断で0 byteファイルが残る | 正式な名前として認識できれば使用済みと扱う。内容が空という理由で番号を再利用しない。 |
| 前回の候補番号を決めたがファイルは作られなかった | 実ファイル等に使用記録がなければ、同番号が再候補になる場合はある。既存ファイルの上書き防止と区別する。 |
| 同名・同番号が見つかった | 他方BANKやシリアルNo.付き名も確認し、未使用の次番号へ進む。 |
| SD未挿入・マウント失敗・一覧取得失敗 | 空のSDと判断しない。採番／保存できない状態を報告する。 |
| 名前変更途中の電源断 | 変更前名・変更後名で確認できるIDを使用済みとして扱う。FAT破損を推測で修復せず、実機で回復挙動を検証する。 |

採番から作成までを単一Loggerの管理下に置き、別の経路で同じ番号を使わない。ファイル作成・名前変更に用いるMicroPython／FAT APIが、存在確認後の上書きを確実に防げるかは実装時に確認する。

### この方式で保証する範囲

SDの両BANKに残り、正常に読み取れる認識対象ログとの番号重複・上書きを防ぐことを基本とする。読めない媒体や、電源断によるファイルシステム破損まで、この採番だけで保護できるとは断定しない。

**BANK循環や手動操作で過去ログをすべて削除した場合、SD交換・初期化をした場合まで、過去番号を永久に再利用しない保証は含まれない。** 必要ならログの存在とは別の永続カウンタが必要になるが、その保存場所・耐電源断更新・摩耗・媒体交換時の扱いは今回の確定範囲に追加しない。

## 6. シリアルNo.取得後の名前変更

既存のTEST終了処理を利用し、仮ID名にも対応させる。シリアルNo.だけの名前にはせず、仮IDを残して同一製品の再試験を区別する。

- 対象は現在の試行で取得した有効なシリアルNo.とし、前試行の値を流用しない。
- 保存可能なQueueの排出、flush、closeが完了してから、同じBANK内で名前を変更する。
- 保存異常時に無理な名前変更を行わない。変更先が存在する場合も置換しない。
- 名前変更失敗時は、変更前ファイルの保全と異常報告を優先する。実際に残った名前を確認せず成功と報告しない。
- シリアルNo.未取得・不正なら開始名のまま保存する。RTCがないこととシリアルNo.未取得を同じ異常として扱わない。

CONTは現行ではTESTのシリアルNo.管理に属さない。複数製品をまたぐ可能性もあるため、TESTのシリアルNo.を無条件に流用してCONTファイルを変更しない。CONTにも製品別命名が必要な場合は、記録区間とシリアルNo.の関連付けを別途決める。

## 7. 変更対象の予定

| 対象 | 必要な見直し |
|---|---|
| logger.py | RTCなし・取得失敗時の命名選択、採番、開始名保持、TEST終了時の名前変更、CONTロールオーバー。 |
| sd_sink.py | 新形式の厳密な認識、両BANKからの番号抽出、同名確認、容量集計・循環対象の整合。 |
| main.py／診断 | RTC初期化失敗だけでなく日時取得失敗も確認。SD状態・RTC状態・ログ保存状態を区別する。変更要否を詳細設計で判断。 |
| MemorySDSink・Hostテスト | 命名契約の見落としを防ぐ。FileSDSinkを用いた再現・境界・異常試験を追加する。 |
| 仕様・手順 | Logger／Cacheに関係する追跡情報、ATE応答・診断の説明、試験仕様、CHANGELOGを整合させる。ATEコマンド追加が必要とは現時点で決めない。 |

採番のためにNF55G通信中のSD走査・write・flushを追加しない。既存のBANKマウント時走査を活用し、開始直前の確認を含む処理時間とATE応答への影響を測定する。ATE優先とNF55G単一Transactionを維持する。

新名をBANK管理へ対応させる際も、所有マーカーと厳密な名前判定を維持する。任意のファイルをログ扱いにして採用・循環削除しない。

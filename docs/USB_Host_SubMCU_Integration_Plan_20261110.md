# QR・DMM用USBホスト下位マイコン／UART連携 開発準備

日付: 2026-11-10／Rev.0（要求整理・設計案）

今回のユーザー指示と添付の過去会話に基づく開発引継ぎ。ハードが揃い次第、開発・デバッグへ進むための準備資料とする。要求として確定した事項、資料で確認した事実、提案、未確認事項を分ける。本書のコマンド名・通信形式・ピン候補は正式APIの確定ではない。実装・Pico配置・基板改造は今回行わない。

11/09のRP2350-USB-Aは候補案だった。今回の指定基板はUSB-Cであり、USB-A向けR13除去等を転用しない。CH9350、かんたんUSBホスト、L-46Xの資料・試験結果は過去記録として保持し、新構成の成立証拠とはしない。今回変更するのはQR／DMM側の接続方針であり、既存ATE接続やNF55G接続を変更する指示はない。

## 2. 接続構成と役割

```text
ATE ── 既存PIA5100／RS232C ── 治具Pico 2
                                ├─ UART1／RS232C ── NF55G
                                ├─ RTC／SD（既存）
                                └─ 追加の双方向UART（PIO方式を検討）
                                           │
                                  RP2350-USB-C
                                  ├─ Type_C1 ── ADCMT 7355
                                  └─ Type_C2 ── BCR-TC2D1BK
```

### USB-Cポート割当て（固定）

基板回路図のコネクタ参照名を配線・ログ・試験記録で共通使用する。機器の入替え、ポート間移行、USBハブの追加は標準構成では行わない。

| 回路図コネクタ名 | 回路・USB経路 | 固定接続機器 | 用途 |
|---|---|---|---|
| `Type_C1` | RP2350ネイティブUSB D+/D-。CC1/CC2は各5.1kΩでVSYS側へ接続 | ADCMT 7355 | DMM制御。実機のUSBクラスとホスト動作を確認 |
| `Type_C2` | PIO-USB。回路ネット`DB_P`／`DB_N`、R11/R12経由でGPIO13/GPIO12へ接続 | Sanwa BCR-TC2D1BK | QR HID読取。PIO-USBホストとして使用 |

この割当ては基板回路図のコネクタ名に基づく固定配線方針。Type_C1はUSB書込みにも使われるため、開発PCからのUSB書込み・USBデバッグ中は7355を外す。別のデバッグ経路は現物確認後に決める。両ポートのホスト同時動作、Type_C2のCC抵抗設定／VBUS給電、7355の実機USBクラス適合は初回受入項目であり、ポート割当てだけで成立済みとは扱わない。

| 担当 | 役割 |
|---|---|
| ATE | 試験工程、測定対象・負荷・接続切替え、取得指示、値の判定、数値付き書込み指示、製品PASS/FAIL |
| 治具Pico 2 | 既存ATE入口、要求受付・下位指示、試験／要求とデータの対応管理、QR解析・Cache／Logger連携、既存NF55G通信 |
| 下位RP2350-USB-C | `Type_C2`でQR HID、`Type_C1`で7355 USB通信、要求に対応するデータ・機器状態・エラーのUART返却 |
| 7355 | 指定条件の測定値を返す。シャント電圧と製品電圧の測定条件は詳細設計で確定 |

下位マイコンからNF55Gを直接制御しない。QR受信・DMM取得だけでSS／ADを書き込まない。FU禁止、NF55G Transaction 1件、Cache無効化・非昇格の既存規則を維持する。

## 3. 資料で確認できた事実と技術上の見通し

- [Waveshare公式RP2350-USB-C資料](https://docs.waveshare.com/RP2350-USB-C)（11/10確認）は、内蔵USBのプログラム用Type-Cと、PIO-USBのType-Cを区別している。PIO-USBはHost／Device用で、CC抵抗設定によるSink／Source切替えを記載。実機の抵抗構成・VBUS給電能力は未確認。
- [BCR-TC2D1BK公式製品情報](https://www.sanwa.co.jp/product/syohin?code=BCR-TC2D1BK)、[取扱説明書Ver.1.0](https://cdn.sanwa.co.jp/support/setsumeisyo/pdf/B/BCR-TC2D1BK_ver1-0.pdf)はUSB HID、Type-C、動作時230mAを記載。HIDレポート形式、配列、終端とRP2350での完全一致は実機確認対象。
- [保存済み7355英文取扱説明書](../reference/ADCMT_7355_20261104/7355-ope--foa-00000201a00-e.pdf)について、11/09調査で§6.4のUSBTMC／CDC、§6.1のBUS選択とインターフェース同時使用不可を確認済み。本書ではその調査記録を引き継ぎ、本文の再調査・実機確認は行っていない。
- [TinyUSB公式](https://docs.tinyusb.org/en/latest/)のHost StackにはHID、CDC-ACM、Hub対応がある。**CDCを第一の実装検討方式**とするが、7355の実機記述子・設定・依存版との適合確認が必要。USBTMCをCDCの代用として無条件に扱わない。

以上から共通USBホスト構成を検討できるが、今回の基板・ハブ・2機器での同時動作を確認したものではない。下位側はC/C++＋Pico SDK＋TinyUSBを開発案とし、PIO-USBを使う場合の依存ライブラリも版を固定する。HIDをPC向けCDCへ出すデモは、DMM向けCDCホストの実装とは別物。

## 4. UARTの配線候補と既存資源の制約

| 治具Pico 2資源 | 現状 | 今回の扱い |
|---|---|---|
| UART0 GP0／GP1 | ATE、115200bps／8N1 | 維持 |
| UART1 GP4／GP5 | NF55G、38400bps／8E1 | 維持 |
| GP9／PIO0 SM0 | 旧QR試作の受信、既定9600bps／8N1 | 追加UART RX候補。資源再確認が必要 |
| GP8 | 旧QR試作でHigh固定 | 追加UART TX候補。送信処理は未実装 |

GP8／GP9のハードUART機能もUART1である。`UART(1)`を追加初期化して第3UARTを作る方法は、NF55Gと独立しないため採らない。**治具側PIO UARTのRX＋TX、下位側ハードUART**を第一の設計案とする。送信用SM、PIO命令メモリ、割込み負荷、リング容量を確認してから割り当てる。現行`src/qr_pio_rx.py`は受信専用で、双方向コマンドリンクへそのまま使用できない。

| 信号候補 | 接続候補 |
|---|---|
| 治具TX | Pico GP8 → 下位マイコンUART RX（下位GPIO未定） |
| 治具RX | Pico GP9 ← 下位マイコンUART TX（下位GPIO未定） |
| 基準 | GND共通。絶縁が必要な配線条件なら絶縁方式を別途設計 |

基板間信号は3.3VロジックUARTを前提に電圧を確認し、RS232C電圧やUSB信号を直接つながない。既存QRホストとの並列接続は行わない。下位GPIOはUSB／PIO／基板内蔵機能と競合しないものを回路図・現物で決める。

通信条件は**115200bps／8N1を候補**とし、既存9600bpsの受信試作実績と区別する。配線長、GND、ノイズ、TX待機High、片側無給電時の逆給電を確認する。フロー制御、Queue容量、1処理あたりの転送上限は未確定。

## 5. コマンド・共有データの整理（設計案）

ATE→Picoの正式コマンドと、Pico→下位マイコンの内部コマンドは別の名前空間とする。次の名称は用途を説明する仮称であり、既存parserへ登録しない。

| 内部指令の仮称 | Pico→下位 | 下位→Pico | 留意点 |
|---|---|---|---|
| LINK_INFO | 接続確認 | FW版、プロトコル版、起動識別子 | 互換性と再起動を検出 |
| DEVICE_STATUS | 機器状態の照会 | QR／DMM各々の接続・利用可否、識別情報 | 状態照会で測定しない |
| QR_ARM | 今回の読取受付開始、要求ID | 受付結果、その後のQR完了／異常 | 光学読取の遠隔トリガ可能とは扱わない |
| QR_CANCEL | 対象要求の受付中止 | 中止結果 | 中止後の遅延データを採用しない |
| DMM_ACQUIRE | 対象・点・測定条件の識別、要求ID | 測定完了データまたは異常 | 実7355コマンド列は別途確定 |
| OP_STATUS | 対象要求の状態照会 | 受付済／処理中／完了／失敗 | 受付応答と処理完了を区別 |

全通信には種別、要求ID、対象機器、payload長、プロトコル版を持たせる案とする。応答と非同期の接続通知を識別し、QR／DMMの内容を混在させない。試験ID・工程・補正点との紐付けはPico側が保持し、旧試験や別要求への誤採用を防ぐ。

物理形式は長さ・境界・誤り検出を備えたフレームを提案する。SOF、エスケープ方法、整数のバイト順、最大長、CRC方式と対象範囲は未確定。QRの生文字列だけを共用UARTへ流す旧方式からは変更が必要。CR／LF／CRLFを受理する既存ATE入口の仕様を、内部UARTへ自動適用しない。

| データ | 保持・返却する情報の案 |
|---|---|
| QR | 要求ID、原文35文字、読取完了、取得時刻または起動後時刻、機器識別、異常。英数字／ハイフン・先頭ゼロ・大小文字を保存 |
| DMM | 要求ID、測定対象・点、7355応答原文、数値と単位、測定機能・レンジ・トリガ条件、取得時刻、オーバーレンジ等の状態 |
| 機器状態 | 接続／切断／列挙失敗、VID／PID・インターフェース、可能ならシリアル、下位起動識別子、Queue破棄件数 |
| エラー | 発生層（UART／USB／HID／DMM）、対象要求、理由、再同期・再接続要否。正式コードは未定 |

測定値の数字だけでは、電圧・電流・補正点・新旧の区別ができない。既存要求では電流は**外部シャントの電圧測定からの換算**を含む。7355の直接電流測定へ変更するとの指定はない。シャント抵抗値・校正値・極性、I=V/Rの実行担当、数値の桁数・丸め・単位を確定してから電流として返す。未確定の換算を下位マイコンへ実装しない。

## 6. 工程・Cache・失敗時の設計方針案

1. QRはATEの明示開始後に受付し、完全な1読取をPicoへ返す。Picoは原文検証・解析を行い、既存QR要求へ連携する。通常Queryから再読取しない。
2. ログ用S/Nは既存決定どおりTEST_START後のQR末尾6桁。ログ名は`SSSSSS_YYYYMMDD_HHMMSS.csv`、日時は開始日時。不正・未取得時は日時名を維持。新しい物理入力の本番接続は未実装。
3. DMMはATEが測定対象・条件を制御し、明示取得指令→下位USB通信→結果をPico→ATEへ返す。新規測定か直前値読出しか、整定待ちとトリガ・完了確認は詳細設計で定める。
4. ATEが値を判定した後、別の数値付き指令でNF55G補正を書き込む。取得値を自動補完しない。測定なしの数値指定書込みも既存要求として保持する。
5. 新取得の開始前に対象の有効性を落とす案とし、timeout・部分受信・切断・下位再起動・Queue overflow時に旧値を新取得成功として返さない。QR／DMMの正式Cache名・寿命・製品交換時の失効条件は未確定。
6. 期限切れ要求への遅延応答、同じ要求IDの重複、再起動後のID再利用を識別する。USB機器再接続で中断工程やNF55G書込みを自動再開しない。

USB／UART／測定のtimeoutは層ごとに管理する。再試行によるトリガ・測定の重複を避けるため、受付済みか不明な要求を無条件再送しない。下位の再送規則は未確定であり、NF55GのCommand Retry最大1回・Response Retry別管理とは別設計にする。NF55G向けACK／NAK規則を下位UARTへ流用しない。

ATEとNF55G処理を優先し、下位UARTはRAM Queueと処理量制限で受け渡す。USBイベントやIRQからSD write／flushを呼ばない。DMM待ちをPico側の長時間blocking処理にしない。ATEが約0.1秒間隔で指令する条件と、DMM測定の完了時間は別であり、受付・完了通知／ポーリングの正式ATE仕様は後続で決める。

## 8. 未確定事項・引継ぎ

- 機器割当ては`Type_C1`=7355、`Type_C2`=QRで固定。Type_C2のCC抵抗実装・ホスト給電、両ポートのホスト同時動作、VBUS給電・保護、USBライブラリの固定版は受入確認待ち。ハブは標準構成に含めない。
- 下位UARTピン、Pico PIO TX／RX資源、baud、フロー制御、フレーム・CRC・長さ上限、要求ID・起動IDの規則。
- 正式ATE／内部コマンド、受付と完了の応答、timeout・取消・重複排除、Queue溢れ・再接続の扱い。

- QR／測定Cache名・失効条件、CSV列、試験／工程／補正点の対応、QR→SS変換と既存AD仕様。

# QRハード結合の実測記録 Rev.0

2026-11-23。ユーザーの配線完了申告後、親Pico COM6／ID `69F7D45962CFDFAD`をUSBで確認し、GP9・115200bpsの受動採取を実施した。

## 確認できた事実

Run_01では60.005秒に9,240byte／60件の診断レコードを受信。連番欠落・解析エラーなし、heartbeatのdrop=0、texts=0、reports=0、flags=12。QR文字列レコードはこの採取区間に存在しなかった。HOST→親のUART経路が動作していることを確認した。

初回のUSB REPL一括出力は9,000byteしかPCへ回収できず、長さ／SHA照合で停止した。親RAMに残る同一の9,240byteを64byte単位・20ms間隔で再回収し、親計算SHA-256 `e1cd1470148e344754283e82aed20cc08484ec92179b991aa3e43733985f2991`と一致した。再採取で元結果を置き換えていない。後続診断の回収出力も同じ速度へ修正した。

途中起動からの採取でboot／board_idレコードは未受信。QR HOSTの現在の個体ID・FW版は未照合。UART経路の受信確認を、ラベル原文の一致・正式ATE Cache／SS連携・製品合格と扱わない。NF55Gコマンド送信なし。採取終了時はQR SM0と測定器SM4/5を停止し、GP9/12/13を入力に戻した。

## Run_02：読取り操作の申告後

ユーザーから「QRを読み取った」と回答あり。2回目の採取は60.006秒・9,240byte／60件。低速出力で初回から長さ／SHA照合が成功した。SHA-256 `525fd9db86c340228b65fc2687f9b04815bbee500862e94cca42af68b269c769`。

全件host_health、解析エラーなし、drop=0、texts=0、reports=0、flags=12。QR文字列は未受信。したがって読取り操作の申告はあるが、原文／35文字分解の実機確認は完了していない。

ソースのhealth flags定義ではbit0がqr_enabled、bit1/2がGP12/13の入力値、bit3がホスト初期化後の定数。flags=12からQR用プロファイルが有効でないことを確認。スキャナー未接続・給電・列挙・対応プロファイルのどれが原因かは、この途中採取だけでは確定できない。USB-A接続とスキャナーの照明／ビープの確認待ち。

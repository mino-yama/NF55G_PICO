# QR読取 実機再確認 Rev.0

2026-11-25。校正作業後の現行治具で、QR読取とキャッシュ照会を実ATEから再確認する。対象は既存QR案件の継続。

## 確認済み

- ホスト単体／Mock回帰は544件成功。QRの35文字分解、読取・照会・明示SSの受付条件は既存試験に含まれる。
- COM5（57600 bps、8N1、応答CR）で親Picoの識別、通信IDLE、SD正常を確認。COM6で親PicoのUSB個体ID `69F7D45962CFDFAD` が列挙された。
- 実ATEで `TEST_START` → `QR_SCAN 60000` が成立し、受付IDを取得した。60秒の受付で `QR_GET?` は `ERR:QR_READING` から `ERR:QR_TIMEOUT` に移行した。試行終了後の照会は `ERR:QR_STALE_ID`、ログ破棄数は0。製品の製造情報を書き換えるSSは未送信。[ATE応答原文](QR_Read_20261125_163701_630341.json)
- 過去の実機では同じ銘板の連続読取、SS一回、D5による書込み後照合まで確認済み。[2026-11-23の実機結果](SS_Write_Readback_Result_20261123_Rev0.md)

## 実機で続けて確認する項目

1. `TEST_START` → `QR_SCAN 60000`。受付後に既知の銘板を読み、読取音を確認する。
2. `QR_GET? <取得ID>` で原文35文字を照会し、既知原文と比較する。 `QR_DATA? <取得ID>` で生成された50文字分のSSデータを照会し、REVの末尾空白、LOT、先頭ゼロを維持した号機を比較する。
3. スキャン操作と読取音を確認した試行でもタイムアウトする場合は、QR HOSTの出力と親Pico GP9受信を観測し、HOSTでの読取成否と親側までの到達を切り分ける。
4. 通常読取成立後、固定接続の電源投入直後にRSTなしで読めるか、読取の遅着が次の受付で採用される条件、必要に応じてSS後の電源再投入保持を個別に確認する。OI-23は継続。[制約とコマンド仕様](SS_Workflow_Spec_20261123_Rev0.md)

# RP2350-USB-C 初回受入・通信準備チェックリスト

日付: 2026-11-10
状態: 事前準備。実機受入・USB列挙・測定器通信は未実施。

本書は[USB Host SubMCU Integration Plan](USB_Host_SubMCU_Integration_Plan_20261110.md)に基づく初回受入手順である。回路名は[基板回路図](../reference/USB_Host_SubMCU_20261110/RP2350-USB-C_schematic.pdf)に合わせる。ポート割当ては固定し、機器を入れ替えない。

全体配線は[治具接続図Rev.3](drawings/NF55G_Fixture_20261110_Rev3/README.md)を参照する。Rev.2以前の図面は履歴であり、旧USBハブ案を今回の接続に適用しない。

## 1. 固定ポート割当て

| 回路名 | 回路上の経路 | 接続機器 | 用途 | 記録ラベル |
|---|---|---|---|---|
| `Type_C1` | RP2350ネイティブUSB D+/D-。CC1/CC2各5.1kΩはVSYS側 | ADCMT 7355 USB Type-B | USB計測器通信 | `PORT=Type_C1; DEVICE=ADCMT7355` |
| `Type_C2` | PIO-USB。`DB_P`／`DB_N`、R11/R12経由GPIO13/GPIO12 | Sanwa BCR-TC2D1BK Type-C | USB HID QR読取 | `PORT=Type_C2; DEVICE=BCR-TC2D1BK` |

USBハブを使わない。割当ての変更や機器間の差替えをしない。`Type_C1`は開発時の書込みにも使われるため、書込み時は7355を外す。二つのUSBホストを同時に運用できるかは初回受入で検証する。

## 2. 受入前に揃えるもの

- RP2350-USB-C実機、基板表裏の写真、基板版またはロット表示
- 本書の回路図・ピン配置図、データシート、ハード設計リファレンス
- BCR-TC2D1BK実機、取扱説明書、読み取り対象の実ラベルまたは承認済み試験QR
- ADCMT 7355実機、FW版、選択BUS、通信マニュアル
- `Type_C1`用USBケーブル（基板側Type-C、7355側Type-B）、`Type_C2`用USB Type-Cデータケーブル
- 電流制限可能な5V電源、電圧計、電流計。可能ならUSB電力計、ロジックアナライザ
- Pico 2、3.3V UART確認用接続線、共通GND
- シャント抵抗の値・校正情報、ATE側での測定条件・配線情報

未選定のハブは準備対象に含めない。旧USBホストのVBUS給電結果を流用しない。

## 3. 回路・電源の受入

機器をUSB端子へ接続する前に行う。未確認の基板改造、抵抗の付け替え、VBUS直結を行わない。

| 項目 | 確認方法 | 合格記録 |
|---|---|---|
| 基板同定 | 製品名・基板版・端子形状を写真記録し、回路図と照合 | `Type_C1`と`Type_C2`を写真上で識別できる |
| `Type_C1` | 回路図のCC1/CC2各5.1kΩとVSYS側接続を照合。D+/D-の導通を目視・計測 | 回路図と実装に差があれば記録して保留 |
| `Type_C2` | R18/R19/R20/R21等のCC選択抵抗実装と`DB_P`/`DB_N`からGPIO13/12への接続を回路図と照合 | Host/Sourceに必要なCC設定が現物で確認できるまで機器を接続しない |
| VBUS | USB機器未接続で各端子のVBUS電圧・極性を測定。Type_C2をHostにする場合の供給元・保護を確認 | 電圧、無負荷電圧、保護方法を記録 |
| 電源余裕 | QR公称230mAに7355 USB負荷・基板消費を加え、起動／読取時の電流を測定 | 電源電圧降下、ピーク電流、電源再投入を記録 |
| 逆給電 | 基板電源OFF時・各USB電源接続時の電源間電圧を安全な測定方法で確認 | 逆流がない、または承認済み保護がある |

Type_C2のCC抵抗設定がHost/Sourceとして成立しない場合は接続を中断し、メーカー資料・実装回路を確認する。回路改造の要否は人間確認なしに決定しない。

## 4. USB通信受入

Pico 2の量産runtimeやNF55Gにはまだ接続せず、下位基板単体で段階的に行う。各段階で機器のポートラベル、USB記述子、通信原文、電源状態を保存する。

| 段階 | 固定接続 | 試験内容 | 合格条件 |
|---|---|---|---|
| A. 開発書込み | Type_C1に開発PC、Type_C2は空 | BOOT／書込み／起動、ファーム版確認 | 再現可能な書込み・起動を確認。PC接続は受入試験時に外す |
| B. QR単体 | Type_C2にBCR-TC2D1BK、Type_C1は空 | USB列挙、HID descriptor/report、実QR読取 | 35文字完全一致、ハイフン・大小文字・先頭ゼロ保持、suffixのバイト値確認 |
| C. DMM単体 | Type_C1に7355、Type_C2は空 | FW／BUS確認、USB class/interface確認、取扱説明書に沿ったID確認と測定取得 | 実機がCDC-ACMまたはUSBTMCのどちらかを特定。新規測定の応答原文・単位・状態を記録 |
| D. 同時接続 | Type_C1に7355、Type_C2にQR | 両方を接続して列挙し、DMM取得待ちの間にQRを読む | 両機器を別ポート・別要求として識別し、データ欠落・重複なく両方を処理 |
| E. 障害復帰 | 割当ては変えない | 各機器を個別に抜去・再接続、基板電源再投入、両方の接続順を変えて比較 | 片側の異常を他方へ誤帰属しない。古い要求・古い測定値を再利用しない |

7355のコマンド文字列・測定条件を推測しない。既存の7355マニュアルと実機設定で確定した手順だけを使う。測定値取得だけでNF55Gへ補正書込みを行わない。値の判定はATE担当。

## 6. Pico 2とのUART通信準備

USB受入後に別工程として実施する。ATE UART0とNF55G UART1は維持する。Pico 2側はPIO RX＋TXを候補とし、ハードUARTを追加で割り当てない。

| 信号 | 暫定候補 | 実機確認 |
|---|---|---|
| Pico 2 TX → RP2350 RX | GP8 PIO候補 | 下位GPIO未決定。基板ピン配置・USB／PIO競合を確認 |
| RP2350 TX → Pico 2 RX | GP9 PIO候補 | 下位GPIO未決定。3.3Vロジック、極性、起動時レベルを確認 |
| GND | 共通GND | 電源系統・逆給電条件を確認 |
| Baud／format | 115200bps、8N1を試験候補としてのみ記録 | 仕様確定前の正式設定にしない |

疎通前に双方を同じ電源状態へ置き、TX/RX交差・共通GND・ロジック電圧を計測する。最初の通信試験はloopbackと短い既知フレームに限定し、フレーム形式・CRC・要求ID・timeoutを確定するまではQR／7355データや量産ATE経路を載せない。

## 7. 初回受入の保留条件

次のいずれかが未確認なら、USB同時接続試験またはPico 2統合へ進まず、記録して保留する。

- 現物基板版と回路図が一致しない、または`Type_C1`／`Type_C2`を物理的に識別できない
- Type_C2のCC Source設定、VBUS供給、過電流保護が確認できない
- USB給電で逆流、電圧降下、予期しないリセットがある
- 7355のFW／BUS／USB classが不明、またはマニュアル準拠の取得手順が未確定
- QRの生HID入力と35文字期待値を照合できない
- 2つのUSB Host経路を同時に動作させるソフトウェア構成が確立していない
- UARTロジック電圧・ピン競合・Pico 2のATE/NF55G通信への影響が不明

## 2026-11-11 Host回路条件の補足・表記訂正

§1／§3にあるType_C1 CCの「VSYS側接続」は原典再照合で誤りと判明。正しくはR5／R6各5.1kΩでGND接続。Type_C2 D+=GPIO12／R12、D−=GPIO13／R11。メーカーUSB-C専用FAQのD+プルアップ撤去対象はR13（GPIO12側）。

[Host回路条件Rev.0](USB_Host_SubMCU_Host_Circuit_Conditions_Rev0_20261111.md)のH0〜H5を今後の具体化した受入案とする。デバッグはPC、機器使用時は外部アダプタからExpander分岐5V・1Aというユーザー指定を反映し、PCと外部5Vを同時直結しない。施工の人間確認・分岐保護・負荷時測定・Host FWとログ経路は別途必要。今回の調査を改造完了や受入合格としない。

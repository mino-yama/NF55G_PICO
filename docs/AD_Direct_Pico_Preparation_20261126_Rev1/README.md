## Rev.1の変更

山田承認によりARのT2を有効ACK受信後100msへ変更。config.T2_AR_MSとcalibration_write.pyのAR選択を反映した配置候補。AD診断T2=1000msは維持。Rev.0は履歴として保存し、次回の配置元は本Rev.1とする。実機固有configの照合・バックアップ・配置hash確認の手順は引き続き適用する。

## ユーザー指定・今回の停止点

次回は親Picoへの書込み（MicroPythonアプリ配置）と配置確認までとする。直接ADの校正検証は、別途、実機とATEで実施する。
実電流を流さない状態で校正値だけを変更すると製品が誤動作する、とのユーザー指示を運用条件として記録する。電流校正は所定の実電流を流し、その時点の実測値をATEから指定する。電圧校正も対象点の実電圧・条件を整える。架空値・例示値だけを実製品へ書き込む診断は行わない。
これは運用条件の記録であり、Picoが実電流の有無を検出・保証する実装を追加したものではない。

## 保存物と確認済み事実

- payload/src/：現在のsrc/*.py 33ファイルのコピー。
- payload/main.py：firmware/main.pyのコピー。親Picoの/main.py用。
- manifest.json：各ファイルの出典・配置先・サイズ・SHA-256。
- コピーは原本とバイト一致。実機用UF2の作成やUSB HOST側の書換えは今回の対象に含めない。
- CALIBRATION_SAMPLE_ENABLED=Falseを保持。EXTERNAL_INSTRUMENT_ENABLED、QR_HOST_ENABLED、QR_HOST_ARM_ENABLEDもソース既定False。実機固有の設定を取り込む前の配置候補である。
- 既存実装報告にはHost／Mock 567件成功の記録がある。これは過去の模擬結果であり、今回の再実行結果・実製品の校正成立を示さない。

## 次回の実施手順（ここまで）

1. 接続先が親Picoであることを確認する。過去記録はCOM6／unique_id=69f7d45962cfdfadだが、現在値を読み取り再確認する。COM番号だけで決めない。
2. 配置中に製品へ指令が流れない接続状態とし、ATEからの指令送信を停止する。校正コマンドによる疎通確認をしない。
3. 現行アプリ・起動ファイル・configを読み取り、この案件内の新規バックアップ先へ保存しhashを記録する。SDログ等の既存データを削除しない。
4. 現行実機configと候補の差分を確認する。外部計測器・QR・応答終端・配線関連等の実機設定を一律に既定値へ戻さない。必要な差分は別の配置版として保存し、マニフェストを更新する。
5. 校正診断の有効化は実機・ATEでの校正検証開始時に扱う。書込みだけの段階ではCALIBRATION_SAMPLE_ENABLED=Falseを保持する。有効化しなければ直接ADはERR:CAL_WRITE_DISABLEDとなる。
6. 配置版について必要なHost Unit／Mock試験を実行し、結果を保存する。候補を変更した場合は変更後のファイルを検証する。
7. アプリを停止し、/src/へ一式を配置する。/main.pyは最後に配置し、全対象ファイルを読み戻して配置版のSHA-256と照合する。途中で失敗した場合は未完了として停止・記録し、校正コマンドを試さない。
8. 接続状態を維持して必要な再起動・起動状態確認まで行う。AD、CAL_WRITE、TEST_START、INFO_REFRESHや自動smokeスクリプトを配置確認のために実行しない。今回の完了条件は配置先・設定差分・全ファイルhash一致・起動状態の記録であり、校正成立ではない。
9. 結果を新規ファイルへ記録して停止する。実電流を伴う製品操作・AD／AR確認は実機とATEによる次工程とする。

## 後日の実機・ATE検証条件

実電流／実電圧と対象回路・Point・極性・単位を整え、ATEで人が読んだ実測値を指定する。診断を有効化した場合も、現在の実装はTEST_START成立と同一試行のINFO_REFRESHによるS1.14B／000001確認が必要。個体制限を独断で解除しない。
ADは別指令のAD_VERIFYで読戻す。通信OKを校正PASSと扱わず、ATEで補正後の実測も確認する。成否不明時は自動再送しない。製品ADの正式T2・ARの実機Timing検証・小数保持・係数反映・再投入保持・量産受入等のOpen Issueは継続する。

# Host動作監視・WDT・親Pico指令による再起動 検討 Rev.1

2026-11-21 ユーザー訂正: 目的は7355/QR本体のRESETではなく、通信経路上のHostマイコンのキャッシュ/通信保持状態のリセット。本資料で機器復旧まで広げた記述は目的の説明として用いず、[現行Rev.2](Host_Communication_State_Reset_Rev2.md)を参照する。本文は検討履歴として保持する。

日付: 2026-11-21。対象: NF55G Pico治具の7355用CDC Host / QR Host。

## 今回の前提と結論案

ユーザー要件: 今後の7355/QRデバッグでエラーを取得し、復旧に問題がある場合に備える。RUN端子/ボタンによるハードウェアリセットが望ましいが、量産ユーザーの操作は困難で、治具構造上RUN配線を引き出せない。Host動作監視、WDT、親Picoからのリセット指令、Host受付入口を検討する。

Rev.0の「手動RESET第一候補」はデバッグ比較用の位置付けに限定する。量産向けの検討主軸を、既存UART経由の管理入口とHost内蔵WDTへ変更する。RUN配線は追加せず、親Pico全体を再起動せずに対象Host/親リンクだけを再確立する構成を提案する。これは設計案であり、WDTやリセット指令の実装・採用パラメータの確定を意味しない。

## 確認済みの実装・資料上の事実

- CDC HostはUSB処理/設定/UART処理をmainループで実行し、fault時は通常要求を拒否する。親リンクも異常を保持する。現行HELLOはUSB readyでfaultがない場合にのみ通常sessionを結ぶため、復旧用の入口にはそのまま使えない。
- QR現行FWはGP0のUART送信のみで、UART受信/管理指令入口はない。Continuousビルドはループ数、PIO USBフレーム数、drop、QR/HID数等を周期出力している。完成QRが来ないだけでHost停止とは判定できない。
- 固定SDK 2.2.0には`watchdog_enable()`、`watchdog_update()`、`watchdog_reboot()`、再起動要因照会APIがある。固定watchdog.cの標準再起動経路はPSMリセットを使い、ROSC/XOSCを除外する設定。RUNリセットと全リセット領域・保持状態が完全に同じとは説明しない。
- SDKはscratch[4]をWDT由来識別等に、指定アドレス再起動ではscratch[5..7]も使用する。保存領域の独自割当はSDK/Boot ROM/既存使用との照合が必要。
- 両HostにWDT/リセット受付は未実装。実機の書込版と現作業ツリーの照合は試験前に行う。

## 1. 動作監視は二段階にする

| 監視 | Hostが報告する情報の案 | 判定の目的 |
|---|---|---|
| Host内部 | main巡回、UART処理、USBタスク巡回、必要なPIO/IRQ進捗、起動段階、内部期限超過 | CPU/処理停止や一部処理の滞留を検出する |
| 親Pico | chip ID/FW/boot ID、heartbeat連番、uptime、上記進捗差分、USB状態、FAULT、最終要求ID/送信段階、エラー/drop数 | Host生存・UART断・USB不調・機器応答timeoutを分ける |

heartbeatの定期報告と明示STATUS要求を候補とする。管理出力にも上限を設け、USB/ATE/NF55G通信を待たせない。mainの生存だけではUSB処理の正常性を証明しないため、各進捗を別に報告する。PIOフレーム数等の進捗条件はUSB動作段階別に定義し、未接続時に不成立な条件を課さない。

7355の長い測定待ちやQR無入力の間もHost処理は進む。これらをWDT期限として扱わない。UART無応答だけではHost停止・配線断・親の受信欠落を断定しない。

## 2. WDTの更新条件と起動監視

- main内の監視担当一か所から更新する。割込み/タイマー/別コアで無条件に更新してmain停止を隠さない。
- 通常時は必要な処理の巡回と内部進捗を確認して更新する。将来マルチコア化する場合は各担当の進捗も条件に含める。
- 機器timeout、USB未接続、書式異常、FAULT保持そのものを理由にWDT更新を止めない。診断/リセット受付が動いているFAULT状態は生存状態として扱う。
- USB初期化に入る前から起動段階を記録し、初期化ハングも検出対象とする。QRの起動待ちやログ排出待ちは有限・協調処理に直し、段階ごとの期限とWDT更新条件を定義する。USB初期化完了後だけWDTを有効にする構成では初期化ハングを拾えない。
- WDTによる再起動後は新しいboot IDで診断/管理入口を立ち上げる。途中要求を再送せず、旧Cache/部分QRを復活させない。
- 期限は現時点で確定しない。最悪巡回時間、USB初期化、既存の起動待ち、割込み遅延、最悪送受信負荷を計測して余裕を決める。正常測定の応答待ち期限とは分離する。
- デバッガ停止中にWDTを止める設定と、量産で停止させない設定を区別する。実機WDT試験ではデバッガ停止による見かけの不発を避ける。

継続再起動を検出するため、保持可能な再起動回数/要因と親側履歴を併用する。繰返し上限到達時は通信復帰を保留する診断状態を提案するが、診断main自体のハング監視は維持する。初期化段階で毎回停止する場合に備え、管理入口をUSB初期化より先に用意する。上限/観測期間は未確定。

## 3. 親Picoからの管理入口

内部管理操作の候補はSTATUS取得、診断snapshot取得、RESET要求、BOOT照合。名称・種別byte・ATE外部公開形式は未確定で、現行ATEコマンドとして登録しない。

### Host側の受付位置

UART受信 → 有限長フレーム復元 → CRC/長さ/対象/版/世代/要求ID照合 → 管理/通常要求振分け → 各担当処理。

管理振分けを`host.fault`や`USB ready`による通常要求拒否より前に置く。USB API、SCPI処理、通常要求Queueの空きに依存せず、FAULT中・USB未接続・通常要求待ち中も管理入口を巡回する。IRQ内ではバッファへの格納等に限定し、再起動の判断はmainで行う。停止したmainは指令を処理できないため、そこはWDTが担当する。

CDCではX1のCRC/長さ等の共通構文処理を利用する候補とし、通常Q本文にRESET文字列を埋め込まない。管理要求が7355へSCPIとして流れないことを保証する。現行H/Qの意味やsession条件を無断で置換せず、管理拡張の版/能力を識別する。

### FAULT中の照合

通常sessionが未成立でも管理照合を可能にする。案は、親の管理challengeへ、対象chip ID・FW・現boot ID・challengeを含めてHostが返答し、そのboot IDとchallengeに結び付くRESET要求だけを受理する方式。通常sessionを復活させる操作ではない。

古いsession/boot ID、CRC不正、途中切れ、誤宛先、重複要求、通常payload中の類似文字列では再起動しない。単一byteやBREAKだけをリセット条件にしない。これは配線内通信での誤受理防止案であり、暗号認証を意味しない。管理に必要な最小状態も破損した場合、無条件受付へ緩めずWDT側で再起動させる。

### 受付後の状態遷移

RUN/FAULT → RESET_PENDING → REBOOTING → BOOT/管理可能 → USB再列挙 → RECOVERY_REQUIRED → READY。

- RESET_PENDINGで新規通常要求を止める。実行中要求があれば成否不明と関連取得CacheのINVALIDを親で保持する。NF55G transaction自体へリセットを波及させない。
- 最終エラー、要求ID、USB送信開始/完了、受信長、リセット要求ID/理由等をsnapshotへ固定する。
- 管理受付応答を有限時間でUART送信する。送信完了を待つならFIFO投入と線上送出完了を区別し、待ち期限を設ける。ACKの意味は「受理」で、再起動完了ではない。ACKが出せなくても無限待ちしない。
- SDKの標準起動経路への`watchdog_reboot(0, 0, …)`を候補にする。BOOTSEL/USB書込モードへ入る操作とは分ける。確定前に、PIO/IRQ/UART/USB再初期化と保持状態を実機で確認する。
- 親は新boot IDのBOOT/照合で再起動を確認する。ACKだけ、UART無応答だけ、LEDだけで完了扱いにしない。
- RESET要求が届いたか不明な場合、まず照合して世代を確認する。同一boot内で重複を実行せず、古いRESETが再起動後に遅着しても実行しない。回数を制限し、無限の再起動要求ループを作らない。

管理用の小さい送受信枠を通常ログと分けて確保し、ログ満杯で受付不能になる事態を避ける。全処理はbyte数/時間/Queue長を制限し、管理要求過多でも量産Timingを阻害しない。

## 4. エラー保存

親側で常時受信した診断をRAM Queueへ保持し、NF55G通信中のSD書込は行わない。記録対象は発生時刻、対象Host、FW/boot ID、phase、fault理由、要求/試行ID、送信開始/完了、受信長、Queue/drop、親が取った処置、再起動後の結果。

応答可能なら再起動前snapshotを取得する。ハング後の取得は保証できないため、直前の周期報告と、予約した保持領域に残す最小要因を使う案とする。scratch/noinit等は有効印・版・整合検査を付け、SDK/Boot ROMとの領域競合および各リセットでの保持可否を確認する。電源断後まで残るとは保証しない。

ログ取得ができない状態でもWDTを止めず、欠落を欠落として報告する。エラーごとのFlash書込は現段階で採用しない。再起動後にSDKの再起動要因と独自記録を併記し、不明はUNKNOWNとする。

## 5. 親リンクだけの復帰と7355/QRの扱い

- 親は対象系統を隔離して、新規要求停止・未完了結果回収・取得Cache失効・UART/パーサー/Queue破棄・session再生成を行う復帰担当を持つ案。正常応答を待つ処理と別の管理経路にし、親Pico全体の再起動を通常の復帰手順にしない。
- Host boot ID変更を処理中/待機中の両方で検知し、Hostが再起動した事実と機器の清浄復帰を区別する。
- 7355はHost再起動後も測定や応答が残り得る。新しいUART sessionだけでは、遅れてUSBから届く旧SCPI応答を識別できない。一定時間の無入力だけでも排除完了を保証しない。機器の取消し/通信クリア/確認手順はメーカー根拠と実機で確立するまでRECOVERY_REQUIREDを維持する。
- 復旧のためのSCPIをHostが勝手に送る方針にはしない。必要ならATE/親の明示手順として設計し、レンジ設定の再確認もATE指定に従う。過去の測定/設定を自動再送しない。
- QRは部分読取りを破棄し、新しい試行/読取り開始との相関を取り直す。USBリーダー側に残ったHID列が新しい読取りへ混入しない境界・再読取り手順を実機で確認する。新boot IDだけで新QRとは扱わない。
- Host再起動は7355本体やQRリーダーの電源再投入ではない。USB機器自身や給電の問題で改善しない場合は、装置異常として停止しATEへ返す。Picoが製品FAILを判断しない。

## 6. QR側に固有の準備

親→QR HostのUART受信経路とHost RX端子が実配線で成立しているかを確認する。親GP8/9の既存予約は変更しない。現在のGP0 TX診断だけで親からのRESETが届くとは扱わず、Host GP1等の候補は現物配線/他用途確認後に決める。RUN引出し不要でもUART戻り線が未接続ならソフトだけでは指令を受け取れない。

既存QR出力フレームを測定器X1へ無断変更しない。QR受信口を追加した新しい評価版で版/能力を識別し、既存デコーダと診断記録を保持する。管理部の内部処理を共通化してもQR/CDCの機器処理・起動状態は別に管理する。

## 7. 実装・受入の順序案

1. 監視/診断記録を先行し、WDT自動復旧は未有効で正常時/異常時の進捗と最悪時間を採取する。
2. 管理受付と親の対象リンク復帰をHost実C/親Mockで検証し、明示RESET→新boot IDまでを単体評価する。
3. 起動/通常ループのWDTを評価版へ追加し、意図的なmain停止・USB初期化停止・割込み滞留を個別試験する。正常なFAULT保持/QR無入力/測定待ちでは発火しないことも確認する。
4. 7355の旧応答排除とQRの新読取り境界を実機で確立する。その後に量産の自動復旧可否・回数・時間を決める。
5. ATE/NF55G/SD共存下で最悪負荷、途中再起動、繰返し再起動、復旧不能を確認する。

| 必須ケース | 期待結果 |
|---|---|
| FAULT/USB未接続/通常要求中のSTATUS/RESET | 管理入口が処理できる。要求中断は成否不明を保持 |
| CRC不正/途中切れ/古い世代/誤宛先/通常SCPI内のRESET文字 | 誤リセットなし、正常要求は境界から再同期 |
| RESET受付応答の欠落/送信詰まり/重複/再起動後の遅着 | 無限待ち/繰返し再起動なし、新boot IDで確認 |
| main停止、USB初期化停止、IRQ異常 | 定義した監視条件でWDT動作、再起動要因を記録 |
| QR無入力/7355長時間待ち/機器切断/FAULT保持 | CPU生存と区別し、不必要なWDT再起動をしない |
| 7355の遅延旧応答/QR途中HID/旧UART応答 | 新要求・新試行のデータとして採用しない |
| 診断Queue満杯/SD停止/片側UART断 | 欠落と復旧不能を報告、ATE/NF55G処理を阻害しない |
| 電源断・連続WDT・管理指令再起動 | 保持記録の成立/不成立を区別し、再起動ループを制限 |

## 未確定事項と今回の範囲

管理フレーム/ATE API、QR RXの実配線、WDT更新条件/各期限、保持領域、再起動回数制限、機器清浄復帰条件は未確定。USB-HOST-RESET-01をOpen維持する。今回のユーザー要件は検討方向の指定として記録し、設計パラメータをCodex判断で確定しない。

今回は資料追加と関連索引への追記のみ。コード/配線/Flash変更、コマンド送信、WDT有効化、Host Unit/Mockおよび実機試験は未実施。検証は文書のローカルリンクと差分の形式確認。

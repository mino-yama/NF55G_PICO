## 6. NF55G送信・受信データ

共通フレームはSTX＋CMD2文字＋DATA＋ETX＋BCC2文字。BCCはCMDからETXまでのXOR。以下のAD／AR形式は現行診断実装・製品レビュー・一部実測に基づき、正式量産仕様の確定とは区別する。

| 項目 | 内容 |
|---|---|
| AD要求 | DATA=TYPE1＋POINT1＋VALUE8、計10文字、全体16バイト。 |
| VALUE8 | 有限IEEE754 float32のビット列を上位側から8桁ASCII HEX化。例1.85 A→3FECCCCD。 |
| AD例 | `AD_4_1_1.85`／`AD_BATT_CHG_P1_1.85`→CMD=AD、DATA=`413FECCCCD`。例値の実機送信指示ではない。 |
| AD応答 | DATA=TYPE1＋POINT1＋ADC6＋計算値欄8、計16文字、全体22バイト。計算値欄は原文を保持し、正常値と決めつけない。 |
| AR要求 | CMD=AR、DATAなし、全体6バイト。対象を絞るDATAは付けない。 |
| AR応答 | 5回路×2点×（ADC6＋REF8）=DATA140文字、全体146バイト。 |
| AR順序 | DISCHG_I P1/P2→BATT_V P1/P2→ACDC12V_V P1/P2→BATT_CHG P1/P2→12VOUT_V P1/P2。 |
| 待ち時間 | AD診断T2=1000ms。AR T2=有効ACK受信後100ms、2026-11-26承認済み。AD正式T2と製品実応答時間は別確認。 |
| 再送 | 現行診断AD／ARはCommand Retryなし。ADから自動ARしない。 |

現行の有限数・構文・float32変換検査は、回路・点ごとの物理上下限検査ではない。通常の0値や極端な有限値を拒否できると扱わない。レビュー対象S1.15_r1の製品側には回路全体の範囲へ丸め込む処理があるが、点別保護ではなく、Picoの保護規格として転用しない。

AD正常／成否不明でDATA／ARをINVALIDにし、使用した測定Cacheを失効。直接指定では同回路のA／B Cacheと照会済み記録を失効させる。STATUS／INFOへAD応答を昇格しない。現行AD_VERIFYはAR CacheをVALIDにしない。

## 8. 書込み保護の設計案（未承認・未実装）

要求された実行位置はNF55GへADを送る直前。取得時だけの検査ではなく、書込みに実際に使う値を確認する。

1. 共通の書込み処理で、回路・製品点・適用規格の有無と、Cache方式なら対応測定点を確認する。
2. Cache方式は同試行・回路・点・有効ID・照会済みを確認し、旧試行／再取得で失効した値を採用しない。追加の時間による鮮度期限は別途決める。
3. 測定原文・単位を確認し、書込み用のA／Vへ正規化した候補を検査する。電流は既定の50A／50mVシャント、Pico担当換算。7355のV原文はV→mV→Aとなり、表示ラベルだけを変更しない。
4. 回路・点別の下限／上限で判定し、範囲外ならADを一切送らずATEへ拒否理由を返す。値の丸め込み・絶対値化・目標値への置換はしない。
5. 通過時だけ既存のfloat32化とAD通信へ進む。境界でfloat32丸めにより範囲外となるケースの扱いも決める。
6. 検査結果はRAMログキューへ記録し、NF55G通信中のSD write／flushを行わない。書込み後は既存Cache失効と成否不明時の安全側処理を維持する。

設定ファイル案の項目は、規格版、回路、P1／P2、対応A／B、単位、下限、上限、対象の使用可否、根拠。形式はCSV／JSON等から後日決定する。規格の欠落・不正・重複・下限上限逆転時は、その対象への書込みを禁止する案。読込みは起動時等にまとめ、書込み直前にファイルI/Oをしない案とする。更新を反映する時期、途中更新禁止、ログへの規格版記録も要決定。

直接指定ADと旧互換入口にも共通検査を適用し、範囲チェックの迂回路を残さない案。ただしTYPE3／5を未規格として拒否するか、規格を設けて許可するかは承認を要する。

拒否エラー名、返却値／下限／上限／規格版の形式、拒否時のCache保持・失効と再測定手順は未確定。事前無送信拒否を、送信後の成否不明と区別する。Picoの範囲判定は書込み保護であり、製品PASS／FAILではない。

範囲内の誤測定・誤配線まで本保護だけで検出できるとは扱わない。ATEの条件設定・配線・負荷・安定待ちの確認と併用する。2点の値差・ADC差の検査を追加する場合は別要求とし、今回の上下限要求から自動追加しない。

## 9. AR小数点問題：事実・推測・未確認

### 確認できた事実

- 過去のS1.14B／UNIT 000001実測で、BATT_CHG P1の0.50／1.85／1.86／2.25 A書込みに対し、AR REF8は00000000／00000001／00000001／00000002だった。
- レビュー対象S1.13／S1.15_r1では、float型のpointを整数変換関数 `int_to_aschex(int32_t, ...)` に渡してAR REF8を作る。AD入力はfloatとして解釈するため、入出力表現に差がある。
- 現行PicoはARのADC6を数値化し、REF8をRAWで残す。回路名付きAD_VERIFYは両値を返し、旧互換照合だけが整数REFとの比較を行う。
- 過去の0.50 A診断ではAD応答計算値欄に非HEX文字も記録されている。入力REFとAD計算値欄を同じ意味の値として扱わない。

### 推測・対応候補

レビュー対象FWではAR出力時の整数化が小数情報を失う箇所と判断できる。ただし接続S1.14Bの内部保存状態までこのソースだけで断定しない。

小数を保持するREF表現の候補は、ADと同じfloat32の8桁HEX、または倍率・符号・丸めを明記した固定小数点。製品側設計の回答・対応FW・旧版識別を確認してから採用する。Picoが整数REFの末尾へ小数を補完したり、AD送信値を読戻し値として返したりしない。

### 未確認事項

- 正式AR REF表現、単位、桁、符号、丸め、ATEへRAW／数値／両方のどれを返すか。
- 接続対象FWのEEPROMに小数が保持されているか、読戻しだけの欠落か。
- AD保存後の実行中係数反映時期と、再初期化・電源再投入の必要性。
- 電源再投入後の保持と、校正後の実測精度。
- 小数を含む元校正値を保全・復元する手段。整数AR原文の保存だけで復元可能とは扱わない。

AR T2=100msは既に承認済みであり、今回の検討で未確定へ戻さない。OI-04／05／16～21等の残課題をCloseしない。

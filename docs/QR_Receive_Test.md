## 原典の確認

- easyusb.manual.20210616.pdf p.1: HIDキーボード準拠QRリーダ対応、TX1から文字列出力。初期設定9600bps、8bit、parityなし、stop 1。I/Oは3.3V。基板5VとUSB VBUSへの給電が必要。

## 実機配線の確認待ち

既存UART0 GP0/GP1はATE、UART1 GP4/GP5はNF55Gに割当て済み。
QR用に第3のハードUARTがある前提で配線しない。
2026-09-26空きピン調査: QR候補はPico側TX=GP8（物理11番）、RX=GP9（物理12番）、GND=物理13番。現行コードとRTC/RS232/SD資料で既存用途との競合は見つからない。ユーザーがこの3本の配線完了を報告済み。

| かんたんUSBホスト | Pico 2候補 | 用途 |
|---|---|---|
| TX1 | GP9 / 物理12番 | QR受信 |
| RX1 | GP8 / 物理11番 | 設定送信等の将来用。読取だけなら未接続 |
| GND | GND / 物理13番 | 共通GND |
| VBUS および 5V | Pico VBUS / 物理40番 | PicoのVBUSから両端子へ分岐して給電（ユーザー接続完了報告） |

GP8/GP9のハードUART機能はUART1で、GP4/GP5のNF55G UART1と独立ではない。既存ATE/NF55Gを維持する構成ではQR側にPIO UARTを推奨する。src/qr_pio_rx.pyにPIO0/SM0・GP9・9600/8N1の受信adapterを追加済み。GP8はHigh固定でホストへ設定コマンドを送らない。PIO0は開始前に全SM停止を読み取り確認した。

物理番号根拠: [Raspberry Pi公式Pico 2 pinout](https://datasheets.raspberrypi.com/pico/Pico-2-Pinout.pdf)。
特にRS232基板がつながったGP5へTX1を重ねて接続しない。TX1はRS232電圧ではなく3.3V UART出力。

信号配線とCOM14は確認済み。ユーザーがPico VBUSからHOST VBUSおよび5Vへの給電接続完了を報告。電圧・消費電流の実測は未実施。残る確認: リーダ消費電流、L-46XのUSB HID設定・Enter suffix、ATE側QR_SCANの実送受信。ユーザーはATE送信可能と報告済み。
未確認のGPIOや電源をコードから設定しない。既存ATE経路は115200bps/8N1/CRLF。

## 試作用インターフェース

リーダは1台、1コマンド1回の手動読取。ATEからのQR_SCANはPico受付の開始であり、リーダへの遠隔トリガではない。
リーダのsuffixをEnterに設定し、ホストのテキストモードでLFまたはCRLFが出ることを確認する。
終端なし、CRのみ、イベントモードは現在対象外。35文字到着のみでは成功にしない。

| ATEコマンド（CRLF終端） | 試作用応答 |
|---|---|
| QR_SCAN | OK:ARMED、またはERR:QR_BUSY/ERR:QR_INPUT_BUSY |
| QR_STATUS? | IDLE/READING/READY またはERR:QR_TIMEOUT等 |
| QR_GET | READY時のみ原文。それ以外ERR:CACHE_INVALID |
| QR_DATA | READY時のみ6項目のkey=value。それ以外ERR:CACHE_INVALID |
| QR_CANCEL | Cacheを破棄してIDLE、OK |

QR_SCANの受付前に旧入力を破棄し、100ms無通信かつ受信FIFO空を確認する。受付後にスキャンする運用が必要。
受付開始と光学的な読取時刻をこのインターフェースだけで厳密に対応付けることはできない。
試験timeoutは10秒（run引数で変更可能）。再受付は旧Cacheを先に無効化する。
35文字超過/不足、許可外文字、途中CR不正、期限切れをERRORとし、部分値を有効化しない。
READY後の追加読取は破棄し、次のQR_SCANまで保持値を変更しない。
ATEには非同期完了通知を送らず、QR_STATUS?で確認する。
FU/FW_UPDATEはERR:FU_DISABLED、SS等はERR:UNKNOWN_COMMAND。NF55G通信経路自体がない。

## 配線確認後の実行手順

1. 生産runtimeを停止した専用試験状態にする。NF55G/SD処理と並行起動しない。
2. qr_reader.py、qr_pio_rx.py、pico_qr_receive_test.pyはCOM14のルートへ配置済み。main.py/boot.pyと既存srcは変更していない。
3. USB REPLを開く。start()がATE UART0 115200/8N1とQR PIO受信9600/8N1を初期化する。PIO RX FIFO8ワード＋RAMリング256byte（実効255byte）を使用する。
4. REPLで以下を実行する。既存runtimeは停止した専用試験状態とし、PIO0/SM0を他用途で使用しない。

```python
from pico_qr_receive_test import start
result = start()
```

5. ATEからQR_SCANをCRLF付きで送信し、OK:ARMED確認後に実ラベルを1回読む。
6. REPLのQR_RAWと6項目、QR_STATUS?のREADY、QR_GET/QR_DATA応答を実ラベルと照合する。
7. Ctrl+Cで停止する。resultはRAM内の試験Cacheとして参照可能。

REPL表示例に用いる合成試験値（製品の正式期待値ではない）:

```text
US250A-CGXE-009491-101A032639000001
product_name US250A-C
item_code GXE-009491-101
product_rev A03
manufacture_year 26
manufacture_week 39
serial 000001
```

開始前スキャン、34/36文字、許可外文字、途中受信timeout、再開始、2回読取も確認する。
Host試験のみではUSB HID相性・GPIO配線・UART受信欠落・REPL表示を検証できない。
REPL printは本番Timing保証のない試験用出力。実機合格後に本番schedulerへの組込みを別途設計する。

## PIO実装と実機準備記録
- サンプリング方式の参照: https://github.com/micropython/micropython/blob/master/examples/rp2/pio_uart_rx.py

## L-46X初期化操作の詳細（ユーザー確認）
ユーザーが初期化操作を具体化: 電源投入時にトリガを10秒以上押して起動させる操作を実施し、「強制初期化」と説明。設定コードによる工場出荷リセットではない。この長押し操作による保存設定の変更範囲・USBモードへの影響は原典未確認。通常の電源投入と区別して記録する。

原典確認追記: メーカー作成L-46Xユーザーズマニュアル第5版p.22 §3.1.4「強制初期化」は、電源投入時トリガ10秒以上長押しを強制起動方法として説明する。ホストとの通信設定をせず読取可能にし、この強制起動中は読取データをホストへ出力しない。従って、この状態での成功音は通常通信復旧の証拠ではない。通常の受信試験はトリガを押さず電源投入し直して行う。先の35文字受信成功時の起動条件は未確定で、D2消灯の根本原因をこの操作だけに断定しない。出典（メーカー作成資料の販売店掲載版）: https://www.j-itecs.co.jp/wp/wp-content/uploads/2020/11/6dfa8720842f8ee09b40c16ba5909b4c.pdf

通常起動でもD2消灯とのユーザー報告。PC直結は現在不可。公開ホストFWの認識条件を確認し、L46X_USB_Recognition_Investigation.mdへ記録。起動後USB接続との比較は未確認、コード/設定変更なし。

# Pico 2 追加機へのコピー準備（2026-11-09）

## 目的と引継ぎ

現在のデバッグ環境を基準として、実ATE・Sample機を使う環境と、2台目Pico 2を使う開発環境を構築する。ハード完成後にコピー作業を行う。既存機の最終的な設置先・各機のCOM番号は接続時に実物で識別して記録する。

## 保存したコピー基準

- 元機識別子: `2d35a1e11ac125e3`。直前までATE側COM20、USB保守側COM14を使用。COM番号はPC上の割当てであり、2台目へ引き継がれるとは限らない。
- [基準マニフェスト](Pico2_Copy_Baseline_20261109.json)に、配置先・サイズ・SHA256を保存。`firmware/main.py`をコピー先`/main.py`、`src/*.py`を`/src/*.py`に配置する全25ファイル。
- [コピー用ZIP](../temp/pico2_copy_package_20261109_run01/pico2_application_20261109.zip)は、PARAM_RESET試験前の実機読戻しマニフェストと全25ファイルのSHA256一致を再確認して生成したアプリケーション一式。ZIP内の`application_manifest.json`はPCでの照合用で、Picoへ配置する必要はない。
- 準備時点の列挙ポートはCOM20のみ。COM14への接続に失敗したため、今回のZIPは現在の本体全体を新規取得したバックアップではない。任意の追加ファイル・boot.py・UF2の一致は今回未確認。
- ZIPおよび試験CSVの`temp/`はGit対象外。ソース・本手順・基準マニフェストはコミット対象。ZIPはこの案件フォルダに保管する。

## ハード完成後の手順

1. 元機と新機に識別ラベルを付け、USB接続先・unique_id・COM番号・配線を記録する。最初は1台ずつ接続して区別する。ATE・NF55Gへの配線が完了するまで、新機の通信試験は行わない。
2. 元機で試験・連続ログ・製品通信が停止していることを確認してから、内部ファイル一覧、OS／MicroPython版、unique_id、Self Check、SD状態を取得する。内部ファイルとSDの必要ログを別々に退避する。元機は書換え・初期化しない。
3. 元機と基準マニフェストを照合する。差分があれば内容と版を記録し、最新の承認済み基準を確定する。既存アプリを保守REPLで中断した場合、同一アプリを再開し、SDを二重mountしない。
4. 新機の既存内部ファイルを退避し、基板型式とMicroPython版を確認する。元機と互換なPico 2向けMicroPythonを用意する。今回UF2のバイナリは確保していないため、入手元・版・SHA256は転送前に記録する。必要なファームウェア書込みは新機だけを対象にする。
5. 新機へ`/src`とその全ファイルを配置し、通常起動入口`/main.py`を最後に配置する。全25ファイルを読み戻し、SHA256を照合する。元機のunique_idやRAM／Cacheを複製する操作は行わない。
6. 配線はREADMEと現行実装を照合する。ATE=GP0/GP1、NF55G=GP4/GP5、RTC=I2C0 GP20/GP21。ADA-5703のGP4/GP5物理分離はHW-01としてOpenのままなので、元機の実配線も記録し、新機で干渉がないことを確認する。製品名だけで旧配線を流用しない。
7. 新機のSDカードは専用に準備する。元SDの全内容をコピーする場合は別途保存・照合し、ログ混在を避ける。認識不良時に自動フォーマットしない。RTCは新機で読出し・必要時刻設定を行う。
8. 新機を通常起動し、`*IDN?`、`PICO_SELF_CHECK?`、`RTC_CHECK?`、`SD_STATUS?`、`COMM_STATUS?`を確認する。識別応答のRev.0だけで版一致を判断せず、ファイルハッシュも確認する。
9. 製品未接続の段階でTEST_START→RTC読出し→TEST_ENDと日時名CSVを確認する。接続後はD1／D5から段階的に実ATEと疎通し、出力監視・送信時刻・実応答・Self Check・ログを記録する。製品制御コマンドは今回のコピー準備では送信しない。

## 引き継ぐ制約・未確認事項

- 全210件のHost／Mock試験成功。実ATE・新機との結合試験、電源切入後の保持、量産Timingは別途確認する。
- FU送信は禁止。D4は量産不使用。QR・DMMはHID／CDC対応マイコン入手後の別開発・結合試験。
- BE-ACCEPT-01（非バックアップ状態でBEがOK）、D4-TIM-01等のOpen Issueは継続。コピーをもって仕様承認・製品PASSとしない。
- 最終製品試験ではPARAMを元RAW50文字に復元済み。以後のBE試験ではD1前後の全フィールド一致、出力変化・瞬断・再起動なしと報告された。これらはNF55G側の状態であり、Picoアプリをコピーして再現するものではない。

# 11月23日 修正・実機確認の引継ぎ Rev.0

ユーザー最新指示：今日は現状で可能なデバッグを実施。明日11月23日は修正を進める。QRを取り付ける予定。自動実行・時刻指定の予約ではない。

## 今日の確認済み

ATE正常・不正入力後の復帰とSD保存照合、RTC進行、STATUS Cache、追加のDATA/INFO Cache、D0/D1/D5とSD/RTCの20回複合動作は確認済み。各試験の詳細と限界は案件内のATE_SD_Check_20261122_181740、RTC_Cache_Check_20261122_183202、本フォルダを参照。

## 修正に向けた優先事項

1. 固定配線・QR追加後の給電、GND、TX/RX、対象個体・FW・起動状態を実物に合わせて確認し、現在の停止状態から再開する。
2. 既定の開発順に沿い、測定器HOSTの状態照会・通常RSTと継続デバッグを進める。CDCは.22.2で送信完了後RX0、.22.1で長時間TIMEOUTを再現済み。.22.3は診断候補であり根本修正済みではない。必要観測で原因を切り分け、対応箇所を修正し、同条件で再試験する。
3. QR取付け後、通信経路・識別、正常/不正入力、取得開始・終了・次試行への持越し防止、シリアル番号とログ反映を確認。正式ATE/Cache/SS連携は既存未確定事項に従い、取付けだけで実装済み・受入完了としない。
4. LOG_CONT_STOP後の約1.6秒遅延は再現候補。許容応答時間と処理区間を確認し、修正対象にする場合は通常SD初期化との関係を計測する。
5. 次の診断コードは結果を分割出力し、boundedな記録量と後片付けを用いる。今回の一括JSON出力のMemoryErrorや、Refresh開始後をQuery後と誤認する観測位置を再使用しない。

## 終了状態

親停止、SM4/5停止、NF55G IDLE、Logger停止、drop/Queue0、CDC fault保持、COM解放。DATA/STATUS/INFOは実機Refresh結果としてVALID。通常運転再開・fault解除・FW配置はこの引継ぎ作成時には行っていない。

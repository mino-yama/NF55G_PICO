## 1. 目的・今回の到達点

LIFE_SETを正式ATEコマンドとして実装し、通常値と範囲外・不正DATAに対するNF55Gの実応答および設定後の読戻しを比較する。量産での使用は未確定。ユーザー指定により値の業務上の制限・試験専用ロック・モード切替は設けない。OI-08はOpen継続とし、PMEを期待するだけで実応答を置換しない。

今回の範囲は実装・Host／Mock試験・本手順作成まで。Sampleは後日準備する。Picoへの追加配置、製品への実送信、実製品の範囲外受理／PME／保持は未確認。COM6開発機はハード組立前であり、この試験には使用していない。

原典: RW11用電源通信仕様書r1 p.5（表記・予約）、p.17（T2）、p.23（SL）、p.32／39（OFF期間クリア）、p.41（積算BATT_DEG読戻し）。

## 2. コマンドの指定

| ATE指定例 | NF55Gへ送るSL DATA | 意味 |
|---|---|---|
| LIFE_SET_0 | 00000000 | 0.0％ |
| LIFE_SET_123 | 07B00000 | 12.3％。指定する整数は0.1％単位 |
| LIFE_SET_4094 | FFE00000 | 409.4％ |
| LIFE_SET_4095 | FFF00000 | 保守用電源識別値。一般の寿命値と区別 |
| LIFE_SET_4096 | 100000000 | 3桁を超えるHEX＋予約5文字、計9文字を送る。切捨てしない |
| LIFE_SET_65535 | FFFF00000 | 計9文字。範囲外試験 |
| LIFE_SET_-1 | -0100000 | 負数をHEX書式化した8文字。不正HEXとしての試験 |
| LIFE_SET_RAW=GGG00000 | GGG00000 | 8文字のまま不正HEXを送る |
| LIFE_SET_RAW=FFF | FFF | 短いDATAを送る |
| LIFE_SET_RAW= | 空DATA | 明示的に0文字を送る |
| LIFE_SET_RAW=07B12345 | 07B12345 | 予約部を非0にする。r1 p.5では予約値は無視 |

LIFE_SET_<VALUE>は符号付き10進整数（小数や0x表記ではない）を最小3桁の大文字HEXへ変換し、予約00000を付加する。範囲による拒否・丸め・桁切捨て・4095の禁止は行わない。

RAWは入力ASCII DATAをそのまま送り、HEX・値・長さ・予約を検査しない。空DATAは末尾=で指定する。ASCIIの1行通信とフレーム境界は維持するため制御文字／非ASCIIは拒否する。既存ATE入口の行長上限は共通のまま。行全体の前後空白は既存Parserで除去される。空白をDATA内部に含める場合はLIFE_SET_RAW=ABC DEF0のように=で指定する。

3桁HEXで表現できる数値は000～FFF＝0～4095で、値域は全て使用済み。4096以上の試験は必ず桁数も超えるため、「8文字の正しいHEX形式のまま数値だけ範囲外」というケースは作れない。負数・不正文字・長さ異常の結果を数値範囲判定と混同しない。

SLのT2は100ms、正常応答DATAは0文字。正常／ambiguous後はDATA CacheをINVALIDにし、STATUS／INFO等へ応答を転用しない。PME／SQE／CMEの明確な拒否では既存Cacheを維持する。QueryやSLからの自動Refreshは行わない。

## 3. 準備と元値の退避

1. Sample／NF55G FW版・製造号機、Pico固有ID・保守COM、ATE側COM、配線・バッテリ・負荷・PS_ON条件を記録する。現行ソースを対象Picoに配置し、25ファイルの読戻しhashを照合する。本実装は今回未配置なので、前回配置済みのCOM14／COM6のままではSLを使用できない。
2. 通信IDLE、Self Check、RTC、SD、ログ破棄数を確認。COM6のRTC／SDは組立後に別途確認してから使用する。
3. TEST_START後、DATA_REFRESHを明示実行。BATT_DEG_TOTAL?とSTATUS_REFRESH、必要な状態Queryを取得する。D0送受信RAW327文字・BCC・現在の積算BATT_DEGの3文字（D0 DATAの0始まり162～164）、0.1％変換後の値を退避する。D0以外のCacheへ昇格させない。
4. D0内のOFF期間データ（0始まり62～91）も保存する。SLはD2受信後等の仕様条件でOFF期間データをクリアするため、元の寿命値を復元してもOFF期間データは元に戻せない。途中のAC OFF／PS_OFF条件も記録する。試験準備のためにSC／D2／D3／D4／CLEARを自動送信しない。D0のCHARGE_END関連は既存OI-03と非破壊方針を引き継ぐ。

## 4. 通常値・範囲外DATAの書込みと読戻し

1. 通常値0、123、4094、4095を1ケースずつ試験する。次に4096、65535、-1、不正HEX GGG00000、短いFFF、空DATA、予約非0の順で必要なケースを実施する。各コマンドの送信DATA・長さ・BCCは第2節と照合する。
2. 各SLのATE応答とNF55G RAWを保存する。正常応答、PME／SQE／CME、NAK reason、HWE、timeoutを区別し、T2・elapsed・Command Retry／Response Retry・ambiguousを記録する。規定Retryは最大1回で、再送はSLの再実行となり得る。PMEが返るかは実機確認事項であり、期待応答へ変換しない。
3. 通信Transaction終了を待ち、DATA_REFRESHを明示送信する。PMEの後でも必ず新しいD0を取得する。旧CacheのQueryを読戻し結果として採用しない。Refresh失敗時は旧値を復活させず、読戻し未確認とする。
4. BATT_DEG_TOTAL?、D0積算欄のBATT_DEG RAW3文字、OFF期間欄、必要なSTATUSを記録する。書込み値と実読戻し値から、拒否・変更なし・受理・桁先頭だけ採用・丸め等の可能性を整理するが、今回FWの観測から正式仕様を決めない。例えば100000000を送って100が返っても、4096全体の保存が成功したとは判定しない。
5. Queryは0.1％単位変換済みなので、FFFは409.5と表示される。RAW FFFが保守識別であることを併記し、Picoで一般値へ補正しない。LIFE_BATT_DEG?は寿命計算欄の別項目であり、設定値の主読戻しにはBATT_DEG_TOTAL?を使用する。D4は量産不使用・Timing課題のため今回の読戻しには使用しない。
6. 同一ケースでのQueryの前後にNF55G送信が増えていないことをログで確認する。製品PASS／FAILはATE側で判断し、Picoは実応答と取得値を返す。

## 5. 元値復元と終了

退避した積算BATT_DEG RAW3文字に予約00000を付け、LIFE_SET_RAW=<退避3文字>00000で明示復元する。DATA_REFRESHとBATT_DEG_TOTAL?でRAWと表示値の一致を確認する。新たにD2を送ってOFFデータを消す手順は加えない。復元失敗／timeoutの場合は未復元・成否不明と記録し、正常復元と報告しない。

TEST_END後にSelf Check、SD、drop数、通信IDLEを保存。CSV・ATE TX/RX・NF RAW・試験ケース表・元値と復元結果・配置hashを案件temp配下の新しい実機試験フォルダへ保存し、Real_Hardware_Test_Log.mdへ追記する。物理電源再投入後の保持と量産採用は今回の実施範囲に含めない。

# 電源投入とRSTの比較 Rev.0

2026-11-14。対象qr-uart-20261114.2／A06FEA01012EC137。

|条件|実機で取得した事実|証跡|
|---|---|---|
|QRなし・電源ONのみ|boot/board_id 2件、309 byte。RST不要でFW起動出力まで実行|[run01](run01_no_qr/Result_Rev0.md)|
|QR接続・電源ONのみ|boot/board_idのみ。QR Aの読取音・LED反応があってもHID認識・文字列なし|[run02](run02_with_qr/Result_Rev0.md)|
|同じ給電・QRのままRST|557msで認識、1716msでAの35文字一致。追加読取指示前に受信|[run03](run03_rst_with_qr/Result_Rev0.md)|

確認できた範囲では、FW自体が起動していないのではなく、QR接続状態の電源投入時にUSB認識が成立せず、RST後に成立する現象。各条件1試行であり、発生頻度・再現条件は未確定。
原因候補: 機器とHOSTの起動順、電源立上り、PIO-USB初期化／接続検出状態等。これらは推測であり確定しない。起動待ち時間の追加だけで解決したとは扱わない。
RST前に読んだデータが後から届く可能性があり、正式親子UART／ATEでは読取要求とデータの対応を確認する必要がある。まだ要求境界・破棄仕様を独断で確定しない。

次の切分け候補は、QRなしで電源投入後にQRをType_C2へ接続し、RSTなしで認識するか確認すること。これでcold-start固有か、後からの接続も検出できないかを比較する。電源投入状態や操作時刻を明示して別試行へ保存する。
FW変更・書込みなし。既知先頭NUL・給電保護・7355／2 Host・正式内部リンクは継続課題。

# Altデコード実機・34文字拒否後の復帰結果 Rev.0

日付: 2026-11-14

## 確認できた事実

- COM22・115200/8N1、受信118889 byte、送信0 byte。終了後ポートを閉じた。
- 起動版 `qr-uart-20261114.2`、基板ID `A06FEA01012EC137`。起動とmountは各1件、途中再起動・再mountの記録なし。
- 772レコード、連番0～771で欠落なし。診断容量1024件未満。HID報告765件。
- 34文字QRはseq380／起動後25200msでkind13理由08（文字数）を1件出力。完成文字列として公開されていない。
- 続く35文字QRはseq769／32829msでkind12を1件出力。次の期待原文と35 byte完全一致。

```text
zZ9-987654321098765432109876543210a
```

- 結果順序は文字数エラー→正常完成の2件だけ。今回の取得範囲に、短い前回文字列の混入・余分な完成出力は認めない。最後の全キー解放報告も取得。
- 期待した文字数エラー以外のreceive_request_failed／oversize_report／init_failed／qr_decode_errorなし。
- 汎用解析器はkind13を含むため`capture_errors`と記録したまま。異常系試験として、期待した理由08の拒否と次の正常完成に一致することを別途照合した。エラーを隠蔽・正常扱いに書換えていない。
- 先頭NUL 1 byteは継続。原文を保持し、解析時のみ明示指定で分離。原文全体のUART形式正常とは判定しない。
- 原文SHA-256: `21174a2c1f01cce18f9c697e323fe19d9601c9a229f2ad1fbe1b1aa1c078bcdd`。

## 判定範囲・残事項

今回の34文字不足・Enter終端のケースについて、拒否後にRSTせず正常35文字へ復帰する動作を実機確認した。製品PASS／FAIL・全体受入完了・Open Issue Closeは行わない。

36文字超過・禁止文字・終端欠落／timeout・切断復帰の実機試験、長時間動作、正式親子UART／ATE連携は未確認。先頭NUL、電源投入だけでの起動差、量産給電保護、7355／2 Hostは継続課題。FW変更・書込みなし。

次候補は36文字超過を拒否した後の正常復帰確認。今回と同様、1起動2読取以内とし、受信準備とRSTを行ってから開始する。

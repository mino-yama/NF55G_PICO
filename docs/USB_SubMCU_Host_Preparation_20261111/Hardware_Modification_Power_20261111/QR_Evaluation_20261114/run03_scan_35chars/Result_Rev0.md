# 35文字試験QR 初回読取ログ Rev.0

日付: 2026-11-14

## 結果

ユーザーの読取完了回答を受領。COM22で39425byte、先頭NUL 1byte＋256レコード（連番0～255）を受信、終了時COM閉。内訳は起動2・列挙3・HID report251件、HID reportは全て8byte。最後の記録時刻は起動後5423ms。

既存の厳密検査はlog at capacityで拒否した。これはログ上限到達であり、読取全体・35文字一致は未確認。FWのRAMは上書きしないため、この採取後に保存されなかったデータがあり得る。破棄数はUARTに出ないため未取得。

## 原文に基づく参考解析

修飾値04は固定TinyUSBのhid.hでLeft Alt、keypad62=0／59～61=1～9。先頭はAltとテンキー00065、00098、00067、00045、その後00048が続き、Altを離す単位でASCIIへ解釈すると先頭22文字はAbC-＋0を18個。期待原文の先頭と一致した。

これは満杯ログの参考的なprefix解釈で、正式デコーダ・完全な読取結果ではない。suffixと末尾・文字コード全域は未確認。QR設定を勝手に変更しない。

## 次の対処

UART診断FWだけを1024件へ拡張して別開発版qr-uart-20261114.1としてビルドする。旧FW・元ログ・旧RAM版は保持。新FWを書き込んだ後、同じ試験QRを1回だけ再採取する。上限到達の拒否・連番検査・末尾完全性未証明は維持する。

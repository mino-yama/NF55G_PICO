# USA単独コード適用後の再採取 結果 Rev.0

日付: 2026-11-14

## 実機結果

ユーザーがUSA単独設定コードを読んだと回答した後、COM22を受信開始。最初のopenはアクセス拒否だったが、対応する常駐captureプロセスは見つからず、1回の再試行でopen成功。別プロセスを停止して解放したわけではなく、初回拒否原因は未確定。

READY後にRST＋3秒待ち＋元の35文字QR1回読取を案内し、ユーザーが完了と回答。60523byte／393レコード、HID388件、連番欠落・容量到達・エラーレコードなし、COM閉。

FW版はqr-uart-20261114.1。HID payload388件は旧Alt設定時と完全一致し、修飾04＋テンキー数字列が続く。英語キーボード直接入力はまだ確認できない。基板側Alt変換コードは戻していない。

## 設定コード・試験QRの独立照合

メーカーKeyboard.pdfのUSA欄とoptioncode.pdfの英語欄を視覚確認し、別のバーコード復号ライブラリzxing-cpp 3.1.1で内容を照合。両方ともCode128のJD200。案内したUSA単独画像も復号結果が1件・JD200であることを確認した。誤った別設定コードを切り出したという証拠はない。

35文字試験QR画像も独立復号し、AbC-＋0を25個＋123456の35byteが期待原文と一致。zxing-cppはGit管理外tools/usb_submcu/barcode-verifyへ導入。画像・PDFの元データや実機rawは変更していない。

## 次の切分け

設定反映・保存・QR本体再起動の条件は資料から確定できていない。ホストRSTだけではQR本体の電源断にならないため、次は外部電源OFFでQRのType_C2プラグを外し、5秒程度待ってから挿し直す。給電再開前から別captureで待機し、QR本体の電源再投入後を調べる。

これは再起動すれば設定反映するという断定ではなく、条件を1つ変える切分け。工場初期化・他設定変更・Alt処理再導入は行わない。PC Type_C1／7355は未接続を維持する。

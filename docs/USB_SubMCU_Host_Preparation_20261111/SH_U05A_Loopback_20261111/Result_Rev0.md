# SH-U05A単体ループバック結果 Rev.0

日付: 2026-11-11／ユーザー指示「①進めて下さい」により実施。

**全112項目成功。送信5113byteと受信5113byteが一致。COM22は試験終了時に閉じた。**

## 対象と設定

- ユーザー申告: SH-U05Aのテスト端子TXD／RXDがジャンパ短絡。前回UARTモードとUART LED点灯を確認。
- 今回のPnP照合: USB-SERIAL CH341 (COM22)、VID1A86／PID5523、Status OK。
- pyserialでCOM22／VID/PID／USB物理位置1-4.3を照合した対象だけを開いた。USB位置に付加されるインターフェース末尾は区切り文字で分離して比較。COM21（追加基板USB）は操作していない。
- 115200bps／8bit／parityなし／stopbit1、フロー制御すべて無効、DTR／RTSともFalse。
- Pythonで送信byteと受信byteを比較。ターミナルのローカルエコー表示を判定根拠にしていない。

送信前の予期しない受信なし、各試験後と終了時の余分な受信なし。送受信HEX原文、件数、送受信量、COM closeは[実機ログrun02](run02/Loopback_Result.json)に保存。保存後に全HEX一致・各長さ・合計5113byte・112件・close済みを別計算で照合した。

## 初回の識別停止と修正

[run01](run01/Loopback_Result.json)はPCの位置表記が1-4.3:x.0になっていたため、旧表記1-4.3との厳密比較で送信前に停止した。送信0byte・COM未オープン。機器異常やデータ不一致ではない。USBインターフェース末尾を正規化し、物理位置・COM・VID/PIDの条件を保持してrun02を実行した。[最終試験スクリプト](check_loopback_final.py)。

## この後の操作・開発

1. SH-U05AをPC USBから抜く。
2. **TXD–RXDの短絡ジャンパを外す。上部のUARTモード選択ジャンパはUART側のまま維持する。**
3. 追加基板への配線はまだ行わず、次工程②で診断TXを有効にしたUART版FWのビルド・検証を準備する。
4. その後、実機直前の改造・電源確認の案内を経て、追加基板GP0診断TX→SH-U05A RXDとGNDのみを接続する。SH-U05AのTXD・5V0・3V3は未接続。

短絡ジャンパ除去はユーザーが行う操作として案内し、除去済みとは記録していない。基板改造・FW書込み・追加基板との送受信は今回実施していない。

## 範囲と未確認

今回確認できたのは、当該PC／USBポート／ドライバ／115200bps設定におけるSH-U05Aの短時間・物理ループバック。端子電圧の実測、外部配線・追加基板のUART、長時間連続受信、QR・DMM・2 Hostの成立とは区別する。USB-SUB-01／02／03はOpen継続。親Pico・追加基板FW・NF55G／ATEコードは変更していない。Host／Mockは今回は再実行していない。

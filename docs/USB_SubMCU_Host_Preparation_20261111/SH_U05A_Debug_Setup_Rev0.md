# SH-U05A デバッグUART採用・接続準備 Rev.0

日付: 2026-11-11／対象: DSD TECH SH-U05Aと追加RP2350-USB-C

## 決定と確認事実

ユーザーがデバッグ用変換器をSH-U05Aと指定。前資料のFTDI候補を置き換え、親Picoを変換器へ転用しない。購入済み・接続済みとの申告、実機COM確認はまだ得ていない。

[メーカー製品ページ](https://www.deshide.com/product-details_1663317.html)はCH341F、TTL信号3.3V、UART 50bps～2Mbps、TX/RX/GND/3V3/5V端子、Windows11対応を記載。115200bps・8N1の診断用途へ使用できる仕様。現物の信号電圧・ドライバ列挙・受信品質は未検証。

[メーカー端子写真](../../reference/USB_Host_SubMCU_Host_Conditions_20261111/SH-U05A/Manufacturer_04.jpg)では、USB-Aプラグを左・部品面正面とした右端6pinの上から3V3、GND、RXD、TXD、GND、5V0。現物ラベルと照合して配線し、色やピン順だけで接続しない。上部にSPI/IICとUARTのモード選択表示があり、UARTモード時はUART LED点灯とのメーカー説明。

製品ページ・原写真2枚は[保存原典と取得hash](../../reference/USB_Host_SubMCU_Host_Conditions_20261111/SH-U05A/manifest.json)へ保存。サポート文書リンクは本文を取得できなかったため、その未読本文からジャンパ番号やドライバ操作を補完しない。

## 初回は受信専用

| SH-U05A | 追加RP2350-USB-C | 使用条件 |
|---|---|---|
| RXD | GP0／UART0 TX | 既存probeの診断TX候補。追加基板上のGP0を現物で照合後に採用 |
| GND | GND | どちらかのGND端子で共通基準 |
| TXD | 接続しない | 初回ログは受信だけ |
| 3V3・5V0 | 接続しない | 追加基板への給電に使わない |

これは治具親PicoのGP0へつなぐ表ではない。親PicoのUART0／ATE、UART1／NF55G、正式下位UARTのピン・内部プロトコルを変更しない。

1. 実機確認直前に基板改造と給電手順の案内を受けてから作業する。今は追加基板へ接続しない。
2. SH-U05AのUSBを外した状態で、現物のモード選択表示に従いUART側に設定。SPI/IIC用端子は使用しない。
3. 信号配線を外したSH-U05A単体をPCへ接続し、UART LEDとデバイスマネージャーのCOM列挙を確認する。必要なら製品ページからメーカー指定のUARTドライバを導入する。今回は導入・COMオープンを行っていない。
4. 端子表示、RXDとTXDが短絡されていないこと、基板側GP0端子を照合する。メーカー写真のRXD/TXD部分にはキャップ状部品が見えるが、その用途や現物実装は未確認。ループバック短絡が実装されている場合は実機受信配線の前に解除する。上部モード選択ジャンパとは区別する。
5. 追加基板の全電源OFF、PC Type_C1ケーブルと7355を外した状態で、GP0→RXDとGNDだけを接続。SH-U05Aの3V3／5V0／TXDは外す。電源切替え・片側無給電時の信号条件を確認する。
6. 診断TXを有効にしたHost評価FW、保護した外部5V枝、QR固定接続を準備した後に受信待ち。SH-U05AはPC USBから、追加基板はExpanderから給電。追加基板Type_C1へPC USBを同時接続しない。
7. 115200bps／8data／parityなし／1stop／フロー制御なし。変換器の実COM番号を指定し、起動ログから保存する。親Pico／ATE／以前の追加基板CDCのCOMを流用しない。

## FWと未実施事項

配布済みqr-probe-20261111.1-ramのUF2はUARTを無効にしたまま。SH-U05Aを接続するだけではこのRAM版からログは出ない。任意GP0 TX分岐は構文検査済み候補であり、UART版のリンク・UF2配布・実機受入は別に記録する。再ビルド指定はscripts/build_usb_submcu_host_probe.ps1 -DiagnosticTxだが、今回は実行・配置していない。

実機前に変換器の現物・モード・端子・COM、GP0診断配線、UART版のビルドとhash、電源保護を確定し、改造案内後に書込み・受信試験へ進む。2 Host構成、35文字QRデコード、正式治具UART、DMMは従来のOpen事項を維持。今回の変更は機材選択と接続準備の文書化のみで、基板・FW・テストコード・既存環境は変更していない。

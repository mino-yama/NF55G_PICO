# QR/DMM共通内部リンク 境界案 Rev.0（未承認）

**2026-11-14 最新方針：物理リンクはQR用Host・7355用Hostそれぞれの独立双方向UARTに分離する。以下の共通フレーム等の検討項目は再利用候補だが、1本の共有リンクは採用しない。経路別の要求・起動・受信状態を管理する。** [現行方針](Split_Host_Architecture_Rev0.md)。


2026-11-14。正式プロトコル・コマンド表ではなく、DMM構成の成立検証と並行して変更を小さく保つための案。USB-SUB-01/03とQR正式APIの未確定項目はCloseしない。

## 境界

USB側: 機器識別・Host・HID/CDC処理と、QR35文字／7355応答原文の取得を担当。
内部リンク: フレーム境界・誤り検出・起動/要求相関・受付と完了/通知・有限Queue/dropを担当。USB実装とは別モジュールにする。
親Pico: ATE入口・試行/工程・6項目分割・QRログS/N・測定対象/補正点・取得値の採用・失効を担当。NF55G指令は従来の共通コアからのみ送る。
正式ATEコマンド、製品判定、SS/AD変換は内部リンクから独立。QR取得や測定をトリガに書き込まない。

## 先に検証すべき採用条件

- QRは現試行かつ受付中の対応要求だけを採用する案。取消・次試行・片側再起動で部分結果と旧有効値を失効する。
- 連続通知の診断kind12を正式結果として無条件転用しない。診断heartbeatを正式応答と混在させない。
- 遅延して届いたリーダー側残留データを、要求IDを後付けしただけで新読取として採用しない。単純な数msのquiet判定で残留を排除できたとは扱わない。この問題は正式QR受付仕様で要確認。
- 受付ACKと処理完了を区別し、CRC異常/timeoutで実行成否不明なら無条件再送しない。NF55GのACK/NAK/retry規則は内部リンクへ流用しない。
- 内部UARTはRAM/非blocking、処理量を制限。親ATEとNF55GのTimingを優先し、通信中にSD write/flushを行わない。

## 決定を保留する項目

親GP8/GP9・PIO TX/RXは候補で、旧RX専用試作との資源競合を確認する。親UART0/1の転用は禁止。下位GP0/GP1は診断TX実績からの候補だが正式採用は未確定。
115200/8N1も候補。ASCII/バイナリ、CRC、SOF/escape、ID幅、Queue数、再送回数、timeout、正式コマンド名/数値は人間確認前に実装しない。
正式Cache名・寿命・ATE API・SSフィールド対応・DMM換算規則は既存Open Issueに従う。

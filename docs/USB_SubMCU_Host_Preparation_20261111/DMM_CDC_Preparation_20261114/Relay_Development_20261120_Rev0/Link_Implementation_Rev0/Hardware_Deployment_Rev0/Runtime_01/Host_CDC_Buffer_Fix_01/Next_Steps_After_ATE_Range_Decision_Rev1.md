# ATEコマンドによるレンジ設定方針と次工程 Rev.1

2026-11-20。ユーザー補足「試験者設定のレンジとは、ATE側のコマンドで決める」に基づきRev.0の解釈を訂正。Rev.0は経緯として保持し、本Rev.1を現行方針とする。今回は計画説明・記録のみ。追加の実機コマンド/設定/測定/電源/Flash操作は行っていない。

## 確定した運用方針

最適レンジはATE側の試験条件に従って決め、ATEからの機器コマンドで設定する。「試験者設定」はATE操作/試験シーケンスによる指定を意味し、前面キー操作を運用上の前提にしない。固定レンジ値とAUTO ON/OFFもATEが明示する。Pico/Hostは指定された本文を中継し、レンジ値の独自置換や自動最適化をしない。レンジ選択の追加調査はここで終了する。RANG20指定→CONF約200V、RANG200→約1100V等の既存原文は参考/経緯として保持し、今後の中継開発を止める理由にしない。Open IssueをCodex判断でCloseせず、運用方針と今回の調査終了を追記する。

## 次工程1: 中継の安定性・異常復帰受入

最初に実施する工程。ATEからレンジ条件を明示設定し、設定後Query/読戻しを受けてから既知入力を固定したREAD?を10回程度、毎回応答完了後に次要求を送る。値の原文/符号/長さ/終端/期限、試行/要求の相関、取りこぼしや予期しない混入がないことを確認する。レンジ最適化や測定精度の製品合否判定は目的に含めない。

次にUSB切断、応答timeout、起動順序/再投入を一条件ずつ切り分ける。エラーがATEへ返ること、送信前後のAMBIGUOUSの扱い、自動再送禁止/fault保持/一要求制約を確認。物理操作が必要な項目は記録を先行してからユーザーへ操作を案内する。

復帰では単なる再接続やquiet時間だけで未完了操作/機器内の遅着が消えたと扱わない。清浄な機器出力状態と親/Host/機器の接続・起動境界を実機で確認してから、新しい明示要求で再開する。故障を自動解除する実装や盲目的再送は加えない。

完了条件: 正常/timeout/切断/復帰について要求/応答原文と実施条件を保存し、古い応答が次要求へ混入しないことを説明できる状態。今回ここまでの異常系はソフト試験と実機の一部のみで、全条件未完了。

## 次工程2: ATE/NF55G/SD等との共存確認

現行のATE優先・NF55G一Transaction制約、BUSY/順序、外部中継中のLogger/SD write抑制を実機で確認する。QR経路も統合する場合は別Hostを含む負荷/PIO資源/IRQ/給電余裕を確認。既存通信Timingを外部測定/Loggerで阻害しないことを評価する。実機NF55Gの状態/試験対象を確認してから指令を選び、FUは送らない。

完了条件: 受入条件ごとのTiming/エラー/ログ欠落の記録があり、量産条件で未確認の範囲が明確な状態。

## 次工程3: 測定取得値をADC校正のCacheへ接続

中継受入後の機能開発。既存calibration_measurement.pyのRAM基盤に、試行/対象/補正点/取得要求を付けて、完成した測定原文・数値・単位を登録しATEへ返す。単位の確認/正規化（必要なV→mV）を機器adapterの責任として設計し、単なるラベル付替えや符号消去を行わない。

既存確定事項: 対象はDISCHG_I/BATT_CHG/BATT_Vの3系統×A/B点、シャント50A/50mV、mVからAへの換算担当は親Pico。正式ATE API/取得完了単位、AD/ARとA/B↔P1/P2対応等の未回答箇所は仕様確認が必要。未確定事項を仮定してNF55Gへ接続しない。

## 次工程4: ATE確認後の明示書込みと総合検証

取得時にはNF55Gへ自動書込みしない。ATEの採用確認後に別の明示指令でCache値をADへ渡す流れを、正式仕様確定後に実装/Mock/実機確認する。数値直接指定方式も維持。Cacheの使用後/成否不明時/TEST_END失効等の既存Hard Rulesを守る。新製品FW追従や未確定AD仕様を今回独断で追加しない。

## 推奨する直近の着手

「ATEからレンジ設定→設定確認→固定入力で連続単発READの安定性確認」から開始し、その後timeout/切断/復帰へ進む。今回は説明依頼のため、新たな測定/切断操作は実施していない。

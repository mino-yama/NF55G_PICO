# 中継実機試行1 結果 Rev.0

2026-11-20 JST。ユーザーの電源投入完了通知後に、COM5のELECOM変換器（056E:5004）から治具ID照合を一回実施。

## 確認事実

- 57600/8N1、flow controlなし、DTR/RTS OFF。受信待受を電源投入より先に開始。
- *IDN?とCRの6byteをPC変換器へwriteし、戻り値6を確認。実RS232波形の送出/到達確認とは区別する。
- 10,093ms待ったが応答0byte。全受信原文のSHA-256は空ファイル値e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855。
- 治具IDが未確認のため、EXT_QUERY 2000 *IDN?は送っていない。NF55Gのコマンドも送っていない。
- 自動再送なし、COM5は採取終了後に解放済み。
- ユーザーはELECOMをATE側RS232C端子（UART0/GP0/GP1）に接続済みと回答。
- 再列挙ではCOM5/COM22だけで、親USB COM6は現れない。外部電源電圧や実機起動をこの一覧からは判定しない。

## 判定・未確認事項

識別中継の受入は未成立。現段階は外部測定器より前の治具ATE受付で停止している。0byteだけで親の未起動・配線・RS232変換器・ファームウェアのいずれとも断定しない。57600を承認済み設定として維持し、根拠なしにbaudrateや製品仕様を変更しない。

次は電源/Host信号を切り離した親単体をPC USBへ接続し、起動ログと実ハード初期化の結果を確認する。配置前のRAM/import検証はGPIOを起動しておらず、通常起動や実PIO初期化の成功を意味しない。

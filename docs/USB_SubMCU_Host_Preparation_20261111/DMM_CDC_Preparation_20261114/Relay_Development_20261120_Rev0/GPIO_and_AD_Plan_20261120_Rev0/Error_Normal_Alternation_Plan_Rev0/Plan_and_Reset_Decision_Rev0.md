# RESET方針の変更と異常/正常交互試験 Rev.0

2026-11-20。ユーザー指示: RUN側パッドへのはんだ付けが難しいため、手動リセットまたは電源入り切りを含めデバッグで決める。初回起動からエラーデータと良品データを交互に送り挙動を確認する。

## 配線/予約の現行方針

Host RUN側パッドのはんだ付け、外部RESET線の取出し、駆動回路の採用は進めない。親GPIO14/22は汎用予備として空け、RESET専用として結線/有効化しない。手動RESET/電源再投入のどちらが必要かは受入試験で判断する。親GP8/9のQR用、GP12/13の測定器Host用というUART配線基準は維持する。

直前の調査で両HostのKey2/RUN接続とRP2350のLowリセット動作は資料上確認したが、物理的な取出しは未実施。AO3400Aメーカー資料は駆動回路検討中に保存した参考資料であり、今回の方針では採用部品/BOM予約を意味しない。関連回路を実装/通電していない。

## 試験の基本順序

1. 電源OFFからATEログを待受し、必要に応じHostの受信/送信線のいずれかを受動採取する。電源ON時刻と初期状態を記録する。
2. 初回に異常データを送り、その後正常データを送る。以後「異常→正常」を繰り返す。異常の種類は一試行ごとに分け、何が復帰/停止を生じさせたか追跡できるようにする。
3. 正常初回起動の基準と比較し、正常要求一件に一応答、誤実行/欠落/重複/旧応答混入の有無、応答時間、受信エラー/故障保持状態を記録する。自動再送で見かけ上成功させない。
4. 停止した場合は原文/状態を保存してから、手動RESETまたは電源再投入を別々の条件で試す。旧応答が残らない清浄な状態と新sessionで再開する。HostだけのRESETで機器内部の未完了測定まで取り消せたとは扱わない。

## データの種類と期待する判定

|区分|例|正常データを続けた時の判定|
|---|---|---|
|ATE行の形式異常|制御文字03/非ASCII/過長行|ERR:FRAME等を返して行終端で区切り、次の正常行が受付可能か確認|
|親Host UARTの形式異常|起動00/不正CRC/不正長/途中切れ/過長|誤実行せず破棄し、次の正しい先頭/CRC/形式/sessionの要求を受理するか確認|
|内容の異常|QR桁数/必須項目不正、測定のOL/NaN/不正数値|通信形式と業務判定を分け、正常な通信なら原文を返す。登録層では異常値をVALID Cacheにしない。正式QR/校正登録層の未実装部分はMock/後続受入へ分ける|
|成否不明/接続異常|送信後timeout、切断、旧session等|現仕様でfault保持となる条件は、その後の正常要求をRECOVERY_REQUIRED等で拒否できることを確認。通常の形式エラーと同じ自動継続を期待しない|

「エラーデータと良品データ」は通信形式と内容の両面に分けて試験ケース化する。Picoが製品PASS/FAILを決める試験ではない。QRの現行診断フレームへ測定器HostのX1をそのまま適用しない。各受信口の正式な契約を使う。

## 実施の境界

最初は副作用のない識別/状態Queryを正常要求として使い、Host上の実C/Mockで異常ケースを再現後、実機へ移す。NF55GのAD/FU等を異常注入用に送らない。ATE/親Host/機器応答のどこへ異常を入れるかを記録し、外部測定の条件やレンジはATE指定を維持する。

タイムアウト/切断後に止まり続けることが規定動作の場合、それ自体を不具合としない。再起動方式を決める材料は、停止条件・エラー状態・旧データ排除・復帰手順の再現性。現時点で手動RESET/電源再投入の採用や追加ソフトRESETは未確定。

今回は計画/配線方針の更新のみで、実機異常送信/RESET/電源/コード/Flash操作は行っていない。既存453件成功の実装は変更なし。

## 責任分担

|担当|持つ機能|
|---|---|
|ATE|SCPI/採用コマンド体系の文字列、設定とQueryの順序、レンジ/積分/トリガ/安定待ち、測定対象の制御、応答内容確認、製品判定、Cache利用書込みの明示指令|
|親Pico 2|外部測定器宛て要求の識別・中継、試行/取得要求との相関、応答原文と状態のATE返却、明示測定取得のCache管理、ATE確認後のNF55G書込み、Logger連携。既存ATE/NF55G優先順位とCache契約を維持|
|RP2350-USB-A Host|USB列挙/識別、CDC line coding・DTR/RTS、USB送受信・部分送受信/終端/timeout/切断管理、親との双方向UART、非blocking診断出力|
|外部測定器（今回の実機: ADCMT 7355）|ATEの指示に従う設定・測定と、応答/機器内エラーの生成|

USBの9600/8N1・DTR/RTS両ONなどの通信接続処理はHostが担当する。SCPIによる測定機能/レンジ設定とは分ける。接続復帰時も親/HostがATEに黙って測定条件を再設定・再測定しない。

## ASCII中継の契約で具体化する項目

ATEがASCII文字列を送る方式でよい。ただしATEの1行を無条件に機器へ転送するのではなく、**外部測定器宛て中継要求の本文として機器コマンドを指定する**。現行7355ではSCPIを用いる。治具自身の`*IDN?`、NF55Gの制御指令、外部測定器の`*IDN?`を宛先で区別する。NF55Gの既存指令体系・FU禁止を迂回する経路にはしない。

- 中継要求にはASCII本文に加え、応答有無、受信完了条件、timeout、試行/要求との対応を定義する。Hostが単に`?`の有無から応答待ちを推測しない。
- 初回は1要求1コマンド、同じ外部測定器で未完了要求を重ねない設計案とする。複数Queryの一括送信や連続データを初回対象とせず、将来対応時に境界を定義する。
- 7355向け終端はCRLF。ATE側要求終端CR/LF/CRLF受理・既定応答CRという既存治具設定とは別に扱う。CRLFをASCII本文へ直埋めして治具の別コマンドとして解釈させず、中継先で所定終端を付加する契約を作る。二重終端を防ぐ。
- SCPI本文の大文字/小文字、コロン、空白、引用符、符号、小数点、カンマは勝手に変更しない。エスケープ/長さ表現と最大長を正式中継フレームで決める。既存ATEの行長512文字にはフレーム分も含めて収める。
- 外部測定器の応答原文は通常の数値Query応答と区別して返す。IDNや機器エラーの空白・カンマ・引用符等を保持する専用応答表現を設計し、既存ATE一般応答の表記契約へ暗黙に混在させない。
- 設定の送信完了は外部測定器の設定受理/実行完了とは異なる。ATEが必要に応じ`*OPC?`、設定読戻し、`:SYST:ERR?`を明示送信して確認する。親/HostがQueryを自動追加しない。現行7355のUSB通信上の制約もATEの手順へ反映する。
- timeoutや切断で成否不明となった設定を自動再送しない。遅着応答を次の要求の応答に採用しない。再接続で未完了要求/断片を失効し、回復状態をATEへ返す。
- 試験用FWの自動IDNなどは診断モード専用。正式なATE制御FWの自動測定手順へ昇格しない。初回TX専用監視版と、ATE指定ASCIIを受ける双方向UART版は開発段階を分ける。

上記は責任範囲と設計条件であり、正式な指令名・API・timeout数値・エラーコードの確定や実装完了を意味しない。

## 任意ASCIIの送受信と校正用Cache

中継した応答が数字に見えるだけで校正Cacheに保存しない。`*OPC?`の`1`や設定読戻し値を電圧測定値として採用してはならない。

校正用の取得では、ATEが明示した測定取得要求に対象・補正点・条件/単位等の対応情報を持たせ、その要求の完成応答だけをCache採用の対象にする設計とする。機器コマンドをATEが指定することと、治具が校正書込みに使えるCacheを検証・管理する責任は両立させる。外部測定器のヘッダ付き数値・OL・エラー・不完全応答の扱いと、シャント換算/単位変換/丸めの担当は別途確定する。

取得→Cache・ATE返却→ATE確認→別の明示書込み指令→NF55G、という確定フローを維持。ATEが確認した取得とCacheが一致することを照合する。書込み時に測定し直さず、使用Cacheは書込み完了で破棄、TEST_ENDで当該試行の全取得Cacheと未完了要求を失効する。ログ履歴は保持。

ASCII中継による測定条件変更と既存取得Cacheの対応・失効方法も詳細設計する。親がSCPI本文を解析して条件を推測する契約にせず、条件識別やCache取消をATE/中継契約で明示できるようにする。独自の無回答変換や製品合否判定を追加しない。

## CDC成立後のデバッグ順

|段階|デバッグ内容|見るもの|
|---|---|---|
|1 単体送受信|IDNの再現、再起動後の列挙/通信設定、完全な1応答|FW版/個体/USB状態、CDC設定完了、送受信原文/byte数/時刻、切断/timeout|
|2 設定と測定|ATEが現行7355のDCV・20V/200V/AUTO・単発測定ASCIIを指定。既知低電圧で確認|設定Query、測定器前面表示、測定原文と期待条件、機器エラー。異なるレンジでの桁/分解能|
|3 親経由中継|ATE→親PIO UART→Host→外部測定器→逆経路の1要求ずつを確認|要求/応答の対応、ASCII文字列保持、宛先混同なし、設定の送信完了とQuery完了の区別|
|4 異常と復帰|無応答/分割受信/過長/遅着/起動失敗/通信切断/誤ったSCPI|上限・期限・機器エラーと中継エラーの区別、次要求への混入なし、自動再設定/再送なし|
|5 QRとの共存|QR読取中の外部測定器通信、片側timeout/再起動とATE/NF55G/RTC/SD併用|他方への混入・欠落なし、ATE優先、NF55G通信Timing、RAM Queue dropとログ相関|
|6 校正への接続|明示測定Cache→ATE確認→別書込み→NF55G読戻し|確認値の同一性、対象/点/試行違いで無送信、完了/TEST_ENDで破棄、AR未確定仕様の回答と実装|

原文監視はUARTログで行う。診断出力はUSB/ATE処理を止めず、有限RAMのdropを明示する。PC受信開始を電源投入より先に行い、文字化け/末尾欠落を測定値の正常応答へ補正しない。連続動作の回数・時間は実運用に合わせて具体化し、根拠なく長時間待機を必須化しない。

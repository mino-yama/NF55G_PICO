# 電圧電流校正とQRの取得値を使う書込み方式

2026-11-14。ユーザー回答により、読取りと書込みの間にATE確認を必須とする。読取り→Cache→ATE確認→別の明示書込み指令で取得値を付加、を確定要件として記録する。正式APIは未確定、今回コードは変更しない。

## ユーザーが指定した到達機能

- 電圧・電流の校正コマンドに付属する形で外部測定の機能を組み込む。
- 数値を直接指定してNF55Gへ書き込む既存方式を維持する。
- それとは別に、DMMから読み取った値を付加してNF55Gへ書き込む方式を用意する。
- QR側も同様に、読み取った情報を対応するNF55G書込みへ利用する。読取・表示・ATEへの返却だけで開発完了とはしない。

## 確定した実行順序

1. ATEが対象・補正点を指定して読取りを指示する。QRもATEの受付指示を起点とする。
2. 親Picoが対応Host経由でDMM/QRを取得し、完成した有効データをCacheへ保存する。
3. Cacheと対応する取得値・状態をATEへ返す。表示/個別Queryから自動再取得しない。
4. ATEが内容を確認し、書き込む場合だけ別の明示書込み指令を送る。
5. 親Picoが指定対象・補正点・試行/取得要求とCacheの対応、有効性を確認し、そのCache値をNF55G書込み形式に変換・付加して送る。
6. 通信結果をATEへ返す。最終判定はATEが行う。

読取りだけではNF55Gへ書き込まない。Cache利用の書込み時にDMM/QRを再取得して値をすり替えない。Cacheなし・INVALID・対象不一致ではNF55Gへ送信せず、ATEへエラーを返す。

従来の「ATEが取得値を数値として再指定する」方式に対し、今回の取得値利用方式では明示書込み指令でCache値を利用する。数値直接指定方式も維持し、どちらを使うか区別できる設計とする。ATE確認中の別取得や遅着によるCache更新を検出するため、取得ID等で確認した値と書き込む値の同一性を保証する契約を詳細設計する。正式なID/引数名・エラーコードは未確定。

QRのSS連携は到達機能に含めるが、既存の先行開発保留の解除時期までは今回断定しない。QR各フィールドとSSの対応、3桁REVから4byteへの変換、年/週からLOTへの対応などの未回答事項は継続する。

## 維持する条件と詳細設計の対象

書込み後の確認はATEが明示Refresh→個別Query→期待値比較を行う。[書込み後確認フロー案](Post_Write_Verification_Flow_Rev0.md)。書込み用取得Cacheは完了で破棄し、照合用期待値はATEで保持する設計案とする。QR/SSはINFO_REFRESH、校正ADはAR_REFRESHが計画経路だが、AR入口・形式・反映時期は未確定/未実装であり現状利用可能とは扱わない。

### 取得Cacheの破棄条件（ユーザー確定）

- 書込み完了時は、その書込みに利用した取得Cacheを破棄しINVALIDにする。DMM/QRとも再使用せず、次回の書込みには再読取りとATE確認を必要とする。
- TEST_END時は未使用分を含め、当該試行のDMM/QR取得Cacheを全て破棄しINVALIDにする。関連する保持値・書込み用解析値・取得対応情報も再利用できない状態にする。
- TEST_ENDで未完了の取得要求も失効させ、その後の遅着応答・完成QR通知でCacheを復活させない。再TEST_STARTで旧試行の値を引き継がない既存要件も維持する。
- ACK_TIMEOUT/RESP_TIMEOUT等で書込み成否不明の場合はHard Rule 15に従いambiguous=Trueとし、関連CacheをINVALIDにして再利用しない。成功完了との区別はATEへ返す。
- この破棄は再書込み用Cacheを対象とし、既に記録したログ・履歴は消去しない。ログ用識別情報の寿命と保存はLogger契約に従い、書込み完了後もログ相関を失わないよう設計する。

正常な完了をどの応答時点で確定するか、明示的な書込み拒否時のCache処理、QRの複数フィールド書込みにおける完了単位は既存仕様と照合して詳細設計する。送信bufferへの投入だけで書込み完了とは扱わない。

最終製品判定はATE、NF55G transactionは常に1件、FU禁止などのHard Rulesは維持する。取得値を使う経路では、対象・補正点・単位・シャント換算・書込み形式、試行/要求との相関、保持値の寿命と失効、欠落・不正値・OL・timeout時の無送信エラーを具体化する。数値直接指定方式にDMM/QRの事前取得を要求しない。

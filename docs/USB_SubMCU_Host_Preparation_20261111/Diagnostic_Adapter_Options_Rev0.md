# Host診断ログ用USB–UARTの選択 Rev.0

日付: 2026-11-11。ユーザー提示の3案の比較。現時点で購入・配線・既存PicoのFW書換えは行っていない。

| 案 | 可否・必要な準備 | 既存親Picoへの影響 |
|---|---|---|
| ① 現開発用Pico2を変換器へ転用 | 専用USB CDC–UART FW、または既存FWへの診断経路の設計・検証が必要。汎用変換器として即使用とはしない | 転用書換えなら現環境を変更するため、保持の意向には適さない |
| ② 新しいPico2を専用変換器にする | 可能。専用FW・GP0/1などのピン設定・115200/8N1・欠落検査を別開発物として準備 | 親Picoを保持できる。専用FWはまだ作成・書込みしていない |
| ③ 3.3V対応USB–UARTを購入 | 診断経路の準備が最も少ない案として推奨。型番とRX/TX信号電圧をメーカー資料で確認 | 親Picoを保持できる |

本番の治具リンクにピンを合わせる場合は、正式UARTピン・フレーム・PIO資源・Timingの確定が別途必要。今回の診断TX候補GP0を正式リンクピンへ自動昇格しない。

購入候補例: [FTDI TTL-232R-3V3](https://ftdichip.com/products/ttl-232r-3v3/)。メーカーはUART信号3.3VとVCC出力5Vを区別している。6pinケーブルのため基板への直挿し前提ではなく、ピンを確認した変換／分岐ケーブルが必要。3V3型番のVCCでも3.3V電源とは扱わない。VCCは今回接続しない。RS232CのUSB変換器や5V信号専用型を代用しない。価格・国内在庫・購入先は未確認、発注は未実施。

初回ログは片方向受信のみ。候補は追加基板GP0 TX→変換器RXとGND共通。変換器TX／VCCは外す。追加基板はExpanderから、変換器はPC USBから給電し、追加基板Type_C1にPCを重ねて接続しない。信号線の片側無給電時の扱い、変換器の型番・端子と3.3V適合を接続前に照合する。

COM番号は購入変換器を実際に列挙して識別する。旧COM6／COM20／COM21をそのまま受信先に流用しない。Host probeでは追加基板のネイティブUSB CDCは起動しない。

ユーザーの最終選択・型番は未確定。③を推奨として準備資料へ記録し、①の親Pico転用や②専用FW作成を無断実施しない。

## 2026-11-11 デバッグ変換器の指定

ユーザーがDSD TECH SH-U05Aを指定。メーカーのTTL信号3.3V・UART仕様を確認し、FTDI購入候補は履歴として保持。[採用機材と端子・モード・接続準備](SH_U05A_Debug_Setup_Rev0.md)を追加。初回は追加基板GP0診断TX候補→SH-U05A RXDとGNDのみ、TXD／3V3／5V0は接続しない。現物・COMと診断GP0採用は未確認、現RAM版UF2はUART無効のまま。FW変更・書込み・実機通信は行っていない。

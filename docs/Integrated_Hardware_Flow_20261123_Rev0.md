# NF55G 実機総合試験フローと確認コマンド

Revision: Rev.0  
Date: 2026-11-23  
状態：実行手順案。未実装工程を含む開発・実機受入用。量産承認前。

TEST_STARTから、SC、製造情報とQR、初期設定、3系統2点補正、計測確認、消去・寿命設定、TEST_ENDまでを一つの試行として追う。付属CSVは同じ工程IDでコマンド・期待応答・照合内容を引ける。表の各行は、直前の応答と確認が成立してから進む。

AD/ARの正式ATE入口と個別照合は未実装のため、この時点で全工程をそのまま連続実行することはできない。実装済みの区間は確認に利用でき、未実装区間は停止点として扱う。診断経路による小数試験は正式API確定より先に実施する。試験を省略して総合合格にはしない。

## 1 適用仕様と実行前に記入する値

対象はNF55G試験仕様書NF55192-G_S1.docx第7章を中心とする通信・補正・計測の総合試験。第1～6章の電気・安全・外観試験等は第13節に整理する。Picoコマンドだけで試験仕様書全体を満たすものではない。

優先するのはAGENTS.md、確定した製品仕様、通信r1、D0 T2のみ300msのユーザー指定、最新のユーザー確定事項。本文の実施順は実機総合確認用に組み立てた案で、原典がこの詳細順序を規定している意味ではない。

| 記号・記入欄 | 記入・決定内容 |
|---|---|
| 対象製品 | 個体ID、搭載製品FW、試験仕様書の版、適用工程・LOT |
| 治具構成 | 親Pico、QR HOST、測定器HOSTの個体・FW・source/UF2 hash、配線図版、設定、有効機能 |
| ATE条件表 | 各工程のAC/DC入力、負荷、信号、接続先、安定待ち、測定回数、許容値、正常終了・異常時の停止条件 |
| `{SC_TIME}` | 実行時に設定するYYMMDDHHMMSS。ATEの採用時刻源と時差許容値を定める |
| `{T_EXT}` | 外部中継・CALの期限ms。1～10000、機能照会＋READを含む総期限。実条件で選ぶ |
| `{T_QR}` | QR受付期限ms。100～60000。取得後の確認時間とは区別する |
| `{CAL_ID}` / `{QR_ID}` | 各応答で得た実際の取得ID。同じ試行・対象・点のものを使用する |
| `{LIFE_VALUE10}` | 設定すべき寿命値の0.1％単位整数。原典画面の0は参考表示で、量産設定値は未確定 |
| 書込み保全 | 製造情報・設定・補正値の元値、変更許可範囲、復元または試験個体の再校正方法 |

波括弧の文字列、角括弧の工程説明は送信しない。期待値は承認された条件表へ記入し、画面例や目標値を合否閾値にしない。

**通信条件**：ATEは57600bps、8N1、要求・応答CRLF。製品側は38400bps、8E1。全要求を逐次送信し、NF55G transactionは常に1件。T2は製品ACK後の待ち期限で、ATE全体の応答待ち時間とは別。D0は300ms、SC/SS/D1/D5は100ms。ATE待ち期限はUART転送・ACK待ち・規定Retry等を含めて設定し、根拠のない固定値を追加しない。

## 2 総合フロー

```text
開始前の構成・接続・保全確認
  → TEST_START → 治具・RTC・SD・通信状態確認
  → SC設定 → 明示D0で日時照合 → 明示D5でFWと元情報取得
  → QR受付 → 原文/SS候補確認 → 明示SS → 明示D5でUNIT・非対象欄照合
  → 初期設定・ERPの読取り照合
  → 外部測定器の識別・DCV設定読戻し
  → 補正3系統×A/B：条件設定→取得→ATE採用→明示AD→別指令AR個別照合
  → 係数反映・2点/中間点・製品計測値・外部実測値確認
  → 必要な制御試験・再投入保持確認
  → 消去前の証跡保存 → データ消去 → 明示読戻し
  → 寿命設定 → 明示D0照合 → 最終状態・情報確認
  → 履歴消去 → 必要履歴ブロックを明示読戻し
  → TEST_END → Self Check・SD・破棄数・CSV確認
  → ATEが製品判定と試験記録の完全性を確定
```

初回開発受入では、第8節の小数切分けを補正正式実装より前に別runで行う。通常製品の量産検査ごとに人工値を書き込む工程ではない。再投入で親が再起動する試験は、開始前後を別試行として記録し、製品IDで関連付ける。

## 3 試験開始とSCと初期情報取得

`実装済`は構文・機能の存在を示す。対象の配置版・配線・有効設定と実機受入は別途確認する。`条件付`の操作は試験条件表で選ばれた場合のみ実行する。

| 工程ID | 送信コマンドまたは操作 | 状態 | 正常応答・読戻し | 照合・次工程の条件 |
|---|---|---|---|---|
| S01 | `TEST_START` | 実装済 | `OK` | 新試行開始。旧製品Cache・CAL/QR取得は失効。開始OKだけでSD保存成立としない |
| S02 | `*IDN?` | 実装済 | `NF55G_PICO_FIXTURE,Rev.0` | 治具識別。固定文字列だけでは配置FWを識別できず、事前hash記録を併用 |
| S03 | `PICO_SELF_CHECK?` | 実装済 | `OK:<詳細>` | ATE_UART、NF55_UART、RTC、LOGGERを確認。前試行のTEST項目があれば前試行の記録と区別 |
| S04 | `RTC_CHECK?` | 実装済 | `OK` | RTCアクセス確認。絶対時刻の校正合格を意味しない |
| S05 | `RTC_DATETIME?` | 実装済 | `YYYYMMDD_HHMMSS` | ログ時刻とATE時刻を照合。SCはRTCを自動参照しない |
| S06 | `SD_STATUS?` | 実装済 | `OK` | 異常なら保存異常を記録。量産での続行可否は条件表による |
| S07 | `SD_USAGE?` | 実装済 | `used_bytes/capacity_bytes/used_percent%` | 空き容量と運用上限90％を確認 |
| S08 | `LOG_DROP_COUNT?` | 実装済 | 10進整数 | 開始基準値を保存。終了時の累積差分と試行別診断を併用 |
| S09 | `COMM_STATUS?` | 実装済 | `OK:state=IDLE` | 通信状態確認。IDLEだけで製品応答成立を保証しない |
| S10 | `CLOCK_SYNC {SC_TIME}` | 実装済 | `OK` | NF CMD=SC。正しい現在時刻を明示指定。NF55Gの日時を変更する |
| S11 | `DATA_REFRESH` | 実装済 | `OK` | SC後の明示D0。日時と同時にD0原文・初回CHARGE_END等を保存 |
| S12 | `NF55_DATETIME?` | 実装済 | `YYYYMMDD_HHMMSS` | 設定値＋経過時間を考慮してATEが照合。完全一致だけを必須にしない |
| S13 | `RETRY_COUNT?` | 実装済 | `OK:cmd=<数>,rsp=<数>` | 直前D0のRetry。SCのRetryも必要ならS10直後に同照会を挿入 |
| S14 | `INFO_REFRESH` | 実装済 | `OK` | 明示D5、INFO Cacheを取得 |
| S15 | `FW_REV?` | 実装済 | 製品FW文字列 | FW書込み仕様書の採用版・期待値とATE照合。末尾空白を保持 |
| S16 | 第4節の製造情報10項目と第5節の設定Query | 実装済 | 各欄の値 | QR/設定変更前の元値を保存。D5全100文字の原文もPC等で保全 |

SC後のD0がCHARGE_ENDへ副作用を持ち得る点はOI-03継続。評価対象の初回D0値は取得直後に保存し、後のD0で上書きして初回評価に使わない。状態監視は必要な時点で明示D1を使う。

`NF_COMM_CHECK?`は現行未実装で常に`ERR:NF55G_NOT_CONNECTED`、送信なし。実通信確認の合格入口には使わず、SC/D0/D5等の実応答で確認する。

## 4 QR取得とSS書込みと製造情報照合

QRを読むだけでは書かない。型式・品目コード・対象製品をATEが確認し、SSの送信候補を照会した後に同じIDで明示書込みする。QR読取開始後に対象ラベルを操作する。

| 工程ID | 送信コマンドまたは操作 | 状態 | 正常応答・読戻し | 照合・次工程の条件 |
|---|---|---|---|---|
| Q01 | `QR_SCAN {T_QR}` | 実装済 | `OK:QR_ARMED:<QR_ID>` | 受付成立。取得完了ではない。返ったIDを保存 |
| Q02 | 対象製品のQRを読取る | 外部操作 | 読取動作 | Q01受付後の当該製品ラベルであることを確認 |
| Q03 | `QR_GET? {QR_ID}` | 実装済 | `OK:QR_GET:<QR_ID>:<35文字原文>` | `ERR:QR_READING`のみ同一IDで待つ。timeout/不正値は中断 |
| Q04 | `QR_DATA? {QR_ID}` | 実装済 | `OK:QR_DATA:<QR_ID>:<100桁HEX>` | HEXを50文字へ復号。製品・変換値・非対象領域をATE確認 |
| Q05 | `QR_WRITE {QR_ID}` | 実装済 | `OK:QR_WRITE:<QR_ID>` | NF CMD=SS。採用確認後のみ送信。成功/成否不明でDATA/INFO失効 |
| Q06 | `RETRY_COUNT?` | 実装済 | `OK:cmd=<数>,rsp=<数>` | 直前SSの通信Retry記録。追加書込みで確かめない |
| Q07 | `INFO_REFRESH` | 実装済 | `OK` | 明示D5。SS応答からの自動INFO更新はない |
| Q08 | `UNIT_REV?` | 実装済 | 4文字 | QR REV3文字＋末尾空白1文字と完全照合 |
| Q09 | `UNIT_LOT?` | 実装済 | 4文字 | QR YYWWと照合。週から月へ換算しない |
| Q10 | `UNIT_SERIAL?` | 実装済 | 6文字 | QR号機と照合。先頭ゼロを保持 |
| Q11 | `FW_REV?` | 実装済 | 6文字 | S15元値と不変照合。QR REVと製品FWは別 |
| Q12 | `ADU_REV?` / `ADU_LOT?` / `ADU_SERIAL?` | 実装済 | 各文字列 | コマンドは1本ずつ送る。元値との不変照合 |
| Q13 | `BBU_REV?` / `BBU_LOT?` / `BBU_SERIAL?` | 実装済 | 各文字列 | コマンドは1本ずつ送る。元値との不変照合 |
| Q14 | D5予約・PARAMETER原文比較 | PC記録照合 | 非対象欄不変 | D5全原文を比較。原文の専用ATE照会は未定義のため取得用PC記録等を用いる |
| Q15 | `QR_CANCEL` | 条件付 | `OK` | 書込み候補不採用時に取消して中断。正常書込み後の必須操作ではない |

現在のSS対象はUNIT_REV/LOT/SERIALのみ。FW6、ADU14、BBU14、予約2はFの変更なし指定。原典§7.1の「UNIT_REV～BBU_SRL」9欄すべての新規書込みをこの入口が満たすわけではない。ADU/BBUは元値確認までとし、書込み要否・値の取得元・正式入口を未確認事項として残す。

同じQRの2件目は最初の確定値を差し替えない。HOST内部で受付前から処理中の旧QRが遅着する境界は未受入。新しいQR_SCANを繰り返すことで解消したと扱わない。QR_STATUS?、QR_PARSE、QR_VERIFY、直接SERIAL系は正式入口未実装。

## 5 初期設定とERPの確認

Q07後のINFOが有効なら以下を照会できる。別の変更操作を挟んだ場合はI01から実行する。設定確認と初期化・書換えは別工程であり、正常品に一律PARAM_RESETを送らない。

| 工程ID | 送信コマンドまたは操作 | 状態 | 正常応答・読戻し | 照合・次工程の条件 |
|---|---|---|---|---|
| I01 | `INFO_REFRESH` | 実装済 | `OK` | 現時点のD5を取得 |
| I02 | `PS_ON_BACKUP?` / `AC_LINK?` / `AUTO_CHARGE?` / `EVENT_ENABLE?` | 実装済 | 各設定値 | 各1本ずつ、承認された初期値表と照合 |
| I03 | `MAX_BACKUP_TIME?` / `MIN_BACKUP_TIME?` / `RESTART_TIME?` | 実装済 | min / sec / sec | 各1本ずつ、単位を含め照合 |
| I04 | `BATT_LOW_THD?` / `BATT_CAP_MAH?` / `BATT_CAP_WH?` / `CHG_IR_THD?` | 実装済 | % / mAh / Wh / mΩ | 各1本ずつ照合 |
| I05 | `BATT_WNG_THD?` / `BATT_ALM_THD?` / `ADU_TEMP_THD?` / `BBU_TEMP_THD?` / `FAN_WNG_THD?` | 実装済 | ℃またはrpm | 各1本ずつ照合。保護設定を独断変更しない |
| I06 | `STATUS_REFRESH` | 実装済 | `OK` | 明示D1。D5ではSTATUSを更新しない |
| I07 | `BURST?` / `PS_OFF_CHARGE?` | 実装済 | 各0/1 | ERP設定を確認。BURST_ON?は外部信号状態なので設定値と区別 |
| I08 | `PARAM_<ITEM>_<VALUE>` | 条件付 | `OK` | 変更指示のある通常10項目のみ。ITEM/VALUEは確認済みのものに置換 |
| I09 | `INFO_REFRESH` → 変更項目Query | 条件付 | `OK` → 指定値 | I08後の明示読戻し。DATA/STATUS/INFOは変更で失効 |
| I10 | `ERP_SET_0_0` / `ERP_SET_1_0` / `ERP_SET_0_1` / `ERP_SET_1_1` | 条件付 | `OK` | 指定された組合せを1本だけ選択。4本順次送信する工程ではない |
| I11 | `STATUS_REFRESH` → `BURST?` → `PS_OFF_CHARGE?` | 条件付 | `OK` → 各0/1 | I10後の設定照合。実充電/バースト動作は外部観測も必要 |

初期設定画面の値を新しい量産合格値として採用しない。保護温度等の仕様差異はOpen Issuesに従う。PARAM_SET全50文字の使用が必要な場合は元値・予約・非変更欄を確認し、`PARAM_SET {50文字}`→`INFO_REFRESH`→各Queryとする。

## 6 外部測定器の識別と設定読戻し

測定対象切替え、入力、負荷、レンジ、安定待ちはATE担当。以下は7355を使う現構成の確認入口で、任意SCPI設定を確定するものではない。電流もシャントのDC電圧で測り、DMMを直接電流測定へ切り替えない。

| 工程ID | 送信コマンドまたは操作 | 状態 | 正常応答・読戻し | 照合・次工程の条件 |
|---|---|---|---|---|
| M01 | `HOST_INFO? METER` | 実装済 | `OK:HOST_INFO:<ID>:<FW>:<NONCE>:<STATE>` | 予定個体・FW・READYを確認。個体不一致/未READYは測定へ進まない |
| M02 | `EXT_QUERY {T_EXT} *IDN?` | 実装済 | `OK:EXT_RX:<byte数>:<HEX>` | 復号して7355型式・個体と照合。終端を含む原文を保存 |
| M03 | `EXT_SEND {T_EXT} {採用済み設定本文}` | 条件付 | `OK:EXT_TX` | ATE条件表のDCV/レンジ/トリガ等。送信完了だけで設定成立としない |
| M04 | `EXT_QUERY {T_EXT} :SENS:FUNC?` | 実装済 | `OK:EXT_RX:<byte数>:<HEX>` | 復号内容がVOLT:DCを示すことを確認 |
| M05 | `EXT_QUERY {T_EXT} :CONF?` | 実装済 | `OK:EXT_RX:<byte数>:<HEX>` | 条件表の機能/レンジ等と照合。前面表示との既存差異は別記 |
| M06 | `EXT_QUERY {T_EXT} :SYST:ERR?` | 実装済 | `OK:EXT_RX:<byte数>:<HEX>` | 機器のエラー応答を復号して記録。中継成功と機器正常を区別 |

EXT_QUERYは測定Cacheへ保存しない。補正用は次節のCAL_MEASUREを使う。EXT/CAL失敗後に同じREADや設定を自動再送しない。開発用HOST_RESETは通常試験の常用手順に組み込まず、第12節で扱う。

### 7.1 補正点の実行表

以下は2026-11-19までにユーザーが確認した現行要求。A/Bと製品ADのP1/P2は同一とは限らず、対応を確認してからADへ送る。目標値ではなく、その条件で取得した実測値を書く。

## 8 小数の実機切分けを先に行う手順

2026-11-23ユーザー指示に従い、AD書込み・AR読出しの実機結果を先に取得し、山田から設計へ確認する。小数挙動の設計回答を待つ必要はない。正式APIと区別した専用診断経路で、対象FW、TYPE/Point、VALUE8の表現・byte順、期限・範囲・元値保全を照合して実施する。

1. 試験個体と元の補正情報を保全する。ARが整数化する場合、ARだけを小数元値の復元用にしない。小数を含む退避または再校正方法を確保する。
2. 無書込みARを取得し、応答全140文字・BCC・対象点のADC/REF8原文を保存する。
3. 許容条件の整数対照値、次に小数を含む実測値を、それぞれ明示ADで書く。送信TYPE/Point/VALUE8、ACK/応答・Retry・時刻を保存する。
4. AD正常後、別操作でARを読み戻し、数値化前のREF8と解析結果を保存する。成否不明では書込みを繰り返さない。
5. 同じ整数部で小数部が異なる2値の比較は、試験専用個体の許容範囲で別runにする。人工値を通常製品の実測校正に混ぜない。
6. 実際の校正後測定、可能なら内部値、規定の再投入前後を別に確認する。内部観測がなければ「内部小数保持は未確認」と記録する。
7. 送信値→VALUE8→REF8→解析値→校正後測定→再投入後の結果を表にして設計へ確認する。正式読戻し形式・照合方法へ回答を反映する。

ARのみ整数でも内部保存が整数とは断定できない。詳細ケース・停止条件は[小数実機試験計画](ADC_Decimal_Hardware_Test_Plan_20261122_Rev0.md)。ここで診断経路を新規実装・実行したわけではない。

## 12 異常時の停止と付属診断

- Refresh失敗後の個別Queryを測定値として採用しない。旧値に戻らずINVALIDを保持する。Control応答内Status、D0内Status/Manufacturing/Parameter、EBを別Cacheへ昇格しない。
- NF応答timeout、最終BCC/FRAME異常等は実行済みの可能性がある。通信結果・ambiguous・失効Cacheを保存し、ATEでAD/SS/CD等を無条件再実行しない。製品側ProtocolのCommand Retry上限1回とATEの再要求を混同しない。
- CAL/EXTのtimeout/切断はfault・遅着境界を確認する。QRはREADINGだけを受付期限内の待ちとして扱い、timeout・STALE_ID・消費済み等を同じ扱いで繰り返さない。
- SD異常でも製品通信は止めない設計だが、保存完全性が必要な工程の量産続行可否は別判断。試験中SD_REINITはBUSY。次のTEST_STARTで欠落を隠さない。
- 中断時も外部電源・負荷を条件表の停止状態へ戻し、実行中通信の成否を記録する。可能ならTEST_ENDで閉じ、閉じられない場合は未完了試行として証跡を保全する。

## 7.1 時刻設定

### 検討の前提

検査仕様書には時間を設定する要求がある。会話では、治具RTCを利用したSCコマンドによる設定と、読出し結果の許容差付き照合が対応候補として挙がっている。これは採用決定や仕様追加を意味しない。

### 量産時に問題となり得る点

| 項目 | 問題点・未確認の内容 |
|---|---|
| 基準時刻の正確さ | 治具RTC自体がずれていると、NF55Gとの照合が一致していても正しい日時を設定できない可能性がある。 |
| RTCの維持管理 | 長期運用、バックアップ電池の消耗、停電や保管後のRTC状態が、設定時刻へ影響する可能性がある。 |
| 時刻系の一致 | 治具RTCとNF55Gで時刻の扱いが異なる場合、一定の時差が生じる可能性がある。 |
| 通信による時間経過 | 設定から読出しまでに時間が進むため、正常でも設定値と読出し値が完全一致しない可能性がある。 |
| 時刻の反映・採取タイミング | SCで時刻が反映される時点と、読出しデータの日時が採取される時点によって、観測される差が変わる可能性がある。 |
| 許容差 | 量産判定に必要な時刻精度と許容差が未決定。厳しすぎると正常品を除外し、緩すぎると設定不良を見逃す可能性がある。 |
| 日時の繰上がり | 秒、日付、月、年の境界をまたぐと、比較方法によっては誤判定する可能性がある。 |
| 読出しデータの鮮度 | 設定前のCacheを参照すると、今回の設定結果を確認できない。 |
| 設定成功の確認 | SCの通信成功だけでは、正しい日時の設定や時計の進行まで確認できない。 |
| 異常時の扱い | RTC異常、SCの実行成否不明、読出し失敗、許容差超過を、量産工程でどう扱うか未決定。 |
| 量産タクト | 読出し照合や異常時の再確認に必要な時間が、量産タクトへ影響する可能性がある。 |

上記は問題点の候補であり、実機で発生を確認した不具合一覧ではない。対応方法の選定、仕様化、実装は本書の現段階の対象外とする。

## 7.1 製造情報 UNIT_REVからBBU_SRLまで

### 検討の前提

検査仕様書の本文には、生産LOT、生産年月、S/N情報を「UNIT_REV～BBU_SRL」まで書き込む旨の記載がある。ただし、この検査工程で新たに書き込むのか、前工程で書込み済みの情報を読み取って確認するのかは、現時点では判断できない。本文に書込みの記載があることと、量産工程での担当・運用が明確であることは区別する。

対象はUNIT、ADU、BBUそれぞれのREV、LOT、SRLの9項目。現行MasterではSRLをSERIALと表記している。Masterに読出し・書込み機能の定義があっても、本検査で書込みが必要と確定したことにはならない。

### 量産時の問題点・不明点

| 項目 | 問題点・未確認の内容 |
|---|---|
| 書込み要否 | 本工程での書込みが必要なのか、事前に書き込まれた情報の読取り確認だけなのか不明。9項目すべてが同じ扱いかも不明。 |
| データ取得元 | 製造情報の一部はQRコードから取得できるとの情報あり。ただし、取得できる項目・形式と、QRコードに含まれない情報の取得元は未確認。 |
| 製品との対応付け | 取得した情報が、検査対象のUNIT、ADU、BBUそれぞれに対応することをどう確認するか不明。 |
| 生産年月の格納先 | 現行Masterの製造情報には生産年月の独立項目がなく、LOT等に含むのか、どの形式で表すのか不明。 |
| 合格基準 | 各項目の期待値、許容される値・形式・範囲が不明。読取り値を何と照合すれば合格なのか判断できない。 |
| 未書込み・不正値 | 空欄、初期値、欠落、不正な形式をどう識別し、どの判定にするか不明。 |
| 再検査・上書き | 書込みを行う場合、既存情報を上書きしてよいか、再検査時にどう扱うか不明。 |

現行Masterに定義された文字数や通信上の形式は、製品としての合格基準を示すものではない。書込み要否、取得元、合格基準について、本書では回答を推測しない。

## 7.1 FW_REVISIONの確認

### 今回の検討上の整理

治具はNF55GのFW_REVISIONを読み取るのみとし、FW書込み仕様書のRevisionとの一致判定はATEに委ねる。治具側で合否判定やFWの書換えを行う内容として扱わない。現行Masterでは読取り項目を`FW_REV?`と表記している。

この責任分担を検討文書に記録する。今回の記録によって確定仕様や実装を変更するものではない。

### 量産時に残る確認事項

| 項目 | 問題点・未確認の内容 |
|---|---|
| ATEの照合元 | 適用するFW書込み仕様書と、そのRevisionの正しい値をATEがどこから取得するか。 |
| 適用版数の管理 | 製品・生産LOT・仕様書改訂に対して、どのFW Revisionを適用するか。 |
| 読取り異常・不一致 | 読取り不能と、正常に読み取った値のRevision不一致を、ATEでどう扱うか。 |

検査仕様書の掲載画面にあるFW Revisionを、そのまま量産の期待値として確定しない。

## 7.3 電流・電圧の補正

### 検討の前提

検査仕様書は、バッテリ充電電流、バッテリ放電電流、バッテリ電圧の3系統について、それぞれ2点間補正を行うとしている。また、「各電流を実測し実測値を入力した後、『SET』で記録する」と記載されている。

補正機能はコマンドとして実装予定である。ただし、補正コマンドの用意と、実測値を自動的にコマンドへ載せることは別の検討事項となる。

### 量産時の問題点

以下は今回の会話で共有されたATE側の制約・懸念を記録したものであり、接続方式や対応方法を決定するものではない。

| 項目 | 問題点・未確認の内容 |
|---|---|
| 実測値の入力 | ATE側で電流測定は可能だが、測定値を「コマンド＋測定値」の形でGPIBへ自動的に載せて送る方法が現状ない。 |
| 自動化の成立 | 測定可能であっても、その実測値を補正コマンドへ引き渡せなければ、補正工程の自動化は成立しない。 |
| 測定器の制御 | 補正工程に必要な測定器の制御ができるか要検討。制御できない場合、実測値の手動入力となる可能性がある。 |
| 手動入力となる場合 | 入力作業が量産タクトへ与える影響や、測定値・補正対象・補正点の取り違えが問題となり得る。 |

実測値の自動入力方法、測定器の制御方法、手動入力の採否は未決定とする。現段階では問題点の記録までとし、具体的な対応案を即時に仕様へ取り込まない。

## 7.5 データのクリア

### 検討の前提

検査仕様書は、試験完了後にCLEAR_DATA、CLEAR_LOG、SET_LIFEでデータをクリアするとしている。各コマンドは実装予定であり、コマンド対応について現時点では特に問題はないと考える。ただし、これは実機で動作や影響を確認済みという意味ではない。

### 量産時の確認事項

| 項目 | 確認したい内容 |
|---|---|
| クリア後の確認要否 | コマンド発行後に、データがクリアされたことの確認が必要か、検査仕様書への明記が必要。 |
| 確認する場合の内容 | 確認が必要であれば、対象データ、クリア後に期待する状態・値、確認するタイミングが明確になっているか。 |
| 各コマンドの影響範囲 | CLEAR_DATA、CLEAR_LOG、SET_LIFEそれぞれが、どのデータを消去・変更するか。残す必要のある情報への影響も確認したい。 |
| 製品動作への影響 | コマンド発行によって製品の動作・状態に変化があるか、試験終了時やその後の動作に影響するか確認したい。 |
| コマンド間の影響 | 発行順序によって結果が変わるか、後続のコマンドや製品動作によってクリア済みデータが再び更新されるか確認したい。 |

現段階では確認事項の記録までとし、クリア後の確認を必須と決定したり、コマンドの影響・発行順序・期待値を推測して確定したりしない。具体的な対応を即時に仕様へ取り込まない。

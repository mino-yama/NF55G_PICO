現在のFWはユーザー指定により開発版として扱う。量産リリース時には、FW版数と、実際に配布・配置したファイル、ハードウェア構成、対応仕様、試験結果、承認記録を対応付ける。

## 2. 版数の付け方の案

採番方式は以下を案とし、正式運用前に人間確認で確定する。表中の番号は例であり、現行版や量産初版への割当てではない。

| 区分 | 表記例 | 扱い |
|---|---|---|
| 開発版 | `v0.1.0-dev.20261111.1` | 開発・評価用。量産承認を意味しない |
| リリース候補 | `v1.0.0-rc.1` | 固定した候補で受入試験を行う。変更時は候補を再識別する |
| 量産初版 | `v1.0.0` | 必要な確認・承認が揃った版に割り当てる候補 |
| 修正版 | `v1.0.1` | 既存インターフェースの互換性を維持する修正の例 |
| 機能追加版 | `v1.1.0` | 既存のATEプログラムとの互換性を維持する機能追加の例 |
| 互換性変更版 | `v2.0.0` | コマンド・応答・試験シーケンス等の互換性を変更する場合の例 |

機能・不具合修正の大小だけでなく、ATEコマンド、Cache、CSV、設定、サブMCU通信、回路構成への影響を確認して採番する。公開済みの版番号に内容の異なる配布物を割り当てず、差替え・再リリースは別版として記録する。外部FW・ライブラリの版番号は提供元の表記を保持する。

## 3. リリースごとの詳細管理表

量産リリース時に以下の項目をリリース記録IDごとに記入し、証跡を参照する。空欄や未確認を承認済みとして扱わない。

| 管理項目 | 記録内容 | 現時点 |
|---|---|---|
| リリース識別 | 記録ID、FW版数、区分、作成日、公開日、作成者、確認・承認者と記録 | 未登録 |
| 対象範囲 | 治具型式・識別番号、適用工程、対象製品と対応製品FW | 最終範囲未確定 |
| ハード構成 | 回路・配線図の版、Pico・サブMCU基板版、RTC、SD、QR、7355、必要な設定・改造 | 最終構成との照合待ち |
| ソース | Gitの完全commit ID、タグ、ソース保管先、必要なサブモジュール・依存版 | リリース対象版未固定 |
| 実行環境 | MicroPython／SDK／コンパイラ等の版、ビルド条件、外部ライブラリ、起動入口と配置先 | 最終版を記録予定 |
| 配布物 | 配布一式の保存先・ファイル名・SHA-256、配置ファイルmanifest | 未作成 |
| ファイルmanifest | 配置先パス、ファイル名、サイズ、SHA-256。設定・起動ファイルも含む | リリース単位で作成予定 |
| 関連FW | 治具Pico 2とUSBサブMCUそれぞれの版・hash、対応する組合せ | サブMCUの採用実装確定後に登録 |
| 対応資料 | 要件、引用原典、ATEコマンド表、Decode、Cache、Logger、回路図、操作・保守手順の版 | 最終配布版未固定 |
| 変更と互換性 | 旧版との差分、変更理由、Issue ID、ATE／CSV／設定／サブMCU通信への影響と移行方法 | リリースごとに記録 |
| 検証 | 同じリリース対象物に対するHost／Mock／実機結果、試験条件・日時・報告書・原本証跡 | 既存個別試験から対象版を整理予定 |
| 制限と残課題 | 未確認項目、回避策、使用条件、Open Issue、残リスクの扱いと人間確認 | Open Issuesを維持 |
| 更新・復旧 | 配置手順、旧版退避、設定・ログの扱い、旧版へ戻す際の互換性・動作確認 | 最終手順未確定 |
| 配布状態 | 候補／承認済／配布済／使用停止、配布先、停止理由、後継版 | 量産版未配布 |

MicroPythonの複数ファイル配置では、配布一式のhashに加え、ファイル別manifestと実機配置後の照合結果を残す。製品NF55GのFWは互換性確認の対象として記録し、治具FWと区別する。NF55GへのFU送信禁止は維持する。

## 5. 量産リリース時の確認欄

- [ ] 対象HW・FW・ソース・設定・依存物・配布ファイルを固定し、再現できる。
- [ ] 要件・資料の版とリリース対象版が対応している。
- [ ] 互換性と変更影響を確認し、必要なATEプログラム・資料を更新した。
- [ ] 同じ対象版で必要なHost／Mock／実機試験を完了し、証跡を保存した。
- [ ] 使用条件、残課題・未確認範囲、残リスクの扱いを人間が確認した。Open IssueのCloseを自動的な条件・結果にしない。
- [ ] 配布物とmanifest、配置・復旧手順、旧版バックアップを揃えた。
- [ ] 確認・承認者、日付、対象リリースを記録し、量産使用可否を明確にした。
- [ ] 各治具の配置履歴と配置後確認を登録した。

確認欄は管理用案であり、試験条件・受入基準・承認者を新たに確定するものではない。

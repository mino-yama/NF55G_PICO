# QR遅着対策の量産ATE経路試験計画 Rev.0

2026-11-26。OI-23。固定配線の復帰連絡後、COM5で治具ID `NF55G_PICO_FIXTURE,Rev.0`、通信IDLE、SD OK、ログ欠落0を確認した。QR用HOSTはPC上でBOOTSELに列挙されなかった。定期通知とスキャナー認識は次回の試験開始時に確認する。測定器HOSTの照会は引き続き `ERR:HOST_TIMEOUT`。今回のQR試験は測定器HOSTを使わない。測定器を含む量産総合試験は復旧後に行う。

前回は保守USBからの一時診断で、旧AのHID読取中に受付を要求し、HOSTの破棄応答後にBだけを受信する手順が3セット連続で成立した。正常な候補データは原文35文字、SS DATA50文字。次はCOM5から量産ATEと同じ経路で、受付、照会、失効を確認する。 [前回の実機結果](QR_Arm_Repeat_Rev0.md) · [現行ATE仕様](../QR_Hardware_Integration_20261123_01/SS_Workflow_Spec_20261123_Rev0.md)

## 1. 統合前の確認とHost Unit／Mock NF55G

双方向処理を親Picoの通常ATE入口につないだ試験版を用意する。`QR_SCAN`／`QR_GET?`／`QR_DATA?`／`QR_CANCEL`／`QR_WRITE` の指令名と既存の取得ID形式を維持する案を優先する。ATEがBをスキャンできると判断する合図は、同一IDのHOST受付応答が確認できた時点とする。現行の `OK:QR_ARMED` の通知タイミング、ATEの応答待ち上限、タイムアウトの起点を事前に確認し、差異はOI-23に記録して仕様確認する。親の応答待ち中もATE／NF55G／SDの処理が滞らないことをMockで検証する。

模擬UARTで旧QRが受付前に完成する場合、受付要求時にHID処理中の場合、受付応答の遅延・欠落・別IDの場合、切断・再起動、取消直後に旧結果が届く場合を再生する。現在の受付IDに対応する結果だけを保持し、READYや書込み可能状態への誤遷移がないことを確認する。旧版HOSTと組み合わせた場合も、双方向試験モードでは旧形式を採用してREADYへ進まないことを確認する。

## 2. COM5の実機試験（SS送信0件）

初めに親PicoとQR用HOSTの版、HOSTの起動記録・個体ID、定期通知とスキャナー認識、治具のIDLE・SD・ログ欠落を確認する。試験版へ置き換える前に両機の現行FWを退避する。試験結果はATE応答原文とUARTの受付ID・連番を突き合わせる。

| 順 | 条件 | 確認する結果 |
|---|---|---|
| 1 | `TEST_START` → `QR_SCAN` → HOST受付応答後にB → `QR_GET?`／`QR_DATA?` | Bの原文が `US250A-CGXE-009491-101A032601000002`、SS候補が全50文字一致。REVは `A03` の右にASCII空白1文字、LOTは `2601`、号機は `000002`。 |
| 2 | 旧AがHID読取の途中で `QR_SCAN`。受付応答後にB | HOSTはAを破棄してから応答。ATEにはBだけが新IDで返る。Aの登録・書込み可能化は0件。 |
| 3 | 確認後に `QR_CANCEL`／`TEST_END`、読取タイムアウト、受付応答の欠落・別ID | そのIDで取得・書込みへ進めず、次の `TEST_START` と新IDで正常に再取得できる。異常注入はまずMockで行い、実機では取消・タイムアウト・再取得から実施する。 |
| 4 | QR用HOSTだけの電源再投入。リーダー接続を維持し、RST操作前の状態を取得 | 起動時刻・定期通知・スキャナー認識を記録し、新IDで再取得できるか確認する。RSTが必要になった場合は、RST前後のログを残す。 |

スキャナーが受付前にトリガーされても、最初のHID報告が受付後まで届かないケースをMockで再生する。HOSTが観測できる情報で識別できるか確認し、実機ではトリガー時点と最初のHID報告を別々に記録できる条件を用意する。識別できない場合は、受付応答後にスキャンする条件を試験結果に明記し、自動除外の評価をOI-23に残す。

## 3. 繰返しと書込み照合

単発の正常・異常系が成立したら、繰返しの初期案は30セット。通常読取20セットと、旧Aの遅着条件10セットを行い、順番と開始条件をログに残す。旧Aの途中を捕捉できなかった回は遅着条件成立として数えず、試行数と成立数をそれぞれ記録する。セット間は量産で想定する間隔をATE側と照合し、決定した値を記録する。受付要求→HOST応答、HOST応答→取得、ATE応答、誤取込み、タイムアウト、SDログ欠落を記録する。

読み取り専用試験を終え、書込み対象のサンプル機と許可を確認できた場合は、1セットだけ `D5` の開始値退避 → Bを取得 → `QR_DATA?` 照合 → `QR_WRITE` → 明示 `INFO_REFRESH` → D5読戻しを行う。UNIT REVの末尾空白・LOT・号機と、ADU／BBU等の開始値を照合する。開始時のUNIT値へ復元し、最後にD5全100バイトの一致を確認する。書込み成否が不明な場合はD5で状態を確認する。製品の最終判定はATE側が行う。

試験記録には各セットの実行時刻、ATE応答、受付ID、HID途中通知、HOST受付応答、完成QR、SS候補、SD状態、復元結果を残す。30セットは次回の初期評価案であり、量産受入の回数・閾値はOI-23で確認する。この文書は立案。実機への書込み・スキャン試験は実施していない。

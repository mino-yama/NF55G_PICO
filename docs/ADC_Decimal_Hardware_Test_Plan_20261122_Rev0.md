# NF55G校正値の小数扱い：実機切分け試験計画 Rev.0

作成: 2026-11-22。案件: NF55G Pico試験治具。状態: 計画のみ・実機未実施。

## 目的と確認済み事項

ユーザー指定により、製品FWの小数点以下の扱いを実機で確認する。先行デバッグ後のADC統合・受入へ組み込み、送信値、製品内部保存値、AR読戻し値、校正後の測定値を分けて調べる。

[既存ソースレビュー記録](ADC_Calibration_Development_20261119.md)ではS1.13/S1.15_r1のADはVALUE8をfloatのビット表現として解釈し、ARはfloat型pointを整数変換してREF8へ出す。この経路では小数情報が失われる。ただし、実機搭載版との一致、内部保存時の小数保持、実際の校正演算への影響は未確認。ARの整数表示だけでEEPROMにも整数が保存されたとは判断しない。

## 開始条件と元値の保全

- 製品個体・搭載FW版、対応するレビューソース/ビルドを特定する。実機版が異なる場合は観測をその版の結果として扱う。
- AD/ARのTYPE・Point・VALUE8表現・応答・T2とA/B対応、試験対象で許容される校正範囲/極性を照合する。未確定のATE入口を使用できる前提にしない。専用診断経路を使う場合は正式APIと区別して送信仕様を記録する。
- 変更前に全校正点のAR原文と製品測定値を保存する。ARが小数を失う場合、その値だけを復元用バックアップにしない。小数を含む元値を保持できる手段、または試験専用個体の再校正手順を準備してから書込みを行う。
- 実測校正は規定の入力・負荷条件で行う。切捨て観測のための人工値書込みは試験専用個体で許容範囲を確認したケースに限定し、実測値による校正と別runにする。
- 外部測定器の単位/レンジ、50 A/50 mVシャント、入力安定条件を記録する。現在のCDC診断版や実機設定を本計画作成時に変更しない。

## テストケース

| ID | 条件・操作 | 主な確認 |
|---|---|---|
| DEC-01 | 無書込みでARを取得し、受信原文とPico解析/ATE表示を突合 | 製品の返却byteと治具側の変換・表示を分離する |
| DEC-02 | 整数値を対照としてAD→正常応答確認→明示AR | 形式/対象/点の基本照合。整数一致だけで小数対応合格にしない |
| DEC-03 | 小数を持つ実測値で3系統×2点を個別にAD→明示AR | 特に0.3 A付近/0.5 A付近/1.85 A付近で、ゼロ化や小数消失を確認 |
| DEC-04 | 同じ整数部・異なる小数部の2値を別試行で指定し、各後にAR | 異なるVALUE8に対しREF8が同じになるか。例1.85/1.86は候補であり実機への既定送信値ではない |
| DEC-05 | 許容範囲内で整数境界の直前/直後を比較 | 切捨て/丸め/範囲制限の候補を切分け。境界を跨げない対象では未実施とする |
| DEC-06 | 同じ条件で小数を保持する内部値を観測可能なら取得 | AD受信後、保存後、AR生成前の値を区別。読み取り専用デバッガ等を使う場合はアドレス/型/版とCPU停止影響を記録 |
| DEC-07 | 正規の2点実測校正前後に、校正点と中間点で外部測定値/製品値を取得 | 物理的効果を確認。人工値比較の結果と混在させない。単独点の一致で全範囲精度を保証しない |
| DEC-08 | 2点の正常書込み後、規定の電源再投入前後でAR/内部値/製品値を比較 | 保存保持と係数反映時期を別確認。ARの整数値が同じだけでは小数保持を保証しない |

DEC-02/04/05の人工値は製品側の制限値に置換されない範囲から選び、試験前に値と期待wire表現を一覧化する。負値/ゼロ/範囲外値は正式仕様と対象条件を確認せず追加しない。DEC-06の内部観測手段がない場合は「内部保持未確認」と記録し、ARや測定値から保存byteを断定しない。

## 1ケースの取得手順

1. TEST_START、個体/FW/試行ID・対象/点・元値・機器条件・時刻を記録する。
2. 外部測定原文、単位正規化後の値、Cache値、ADへ格納する値とVALUE8を記録する。規定がfloat32ならその表現による精度差と、小数全体の消失を分ける。byte順は正式契約に従い推定しない。
3. ADを明示1回実行し、送信フレーム/BCCとACK/応答/Retry/ambiguousを保存する。成否不明なら当該ケースを止め、同値の自動再書込みをしない。
4. 正常書込み後、別の明示操作でARを取得する。全140文字が揃いフレーム/BCCが正常であることを確認し、対象ADC/REF8の原文と解析結果を保存する。別対象・別点が変化していないかも確認する。
5. 可能な内部観測、規定の明示測定読出しを別操作で行う。Queryによる自動Refreshはしない。観測時刻と電源再投入の前後を明示する。
6. TEST_END、SD保存状態・drop/Queueを確認し、PC側rawとCSVを保存する。TEST_STARTだけで全wire原文がCSVに残るとは想定せず、不足はPC記録で補う。
7. ケース終了時は復元/再校正結果と最終状態を記録する。復元不能なら運用復帰済みとせず、その個体の状態を明示する。

## 結果の読み方

| 観測 | 結論の範囲 |
|---|---|
| AD wireのVALUE8が期待と異なる | 製品へ到達する前の値生成/換算/符号/桁処理を調査 |
| AD wire正常、内部は小数保持、ARだけ整数 | 当該版・条件でAR出力経路の情報欠落を確認 |
| AD wire正常、内部保存値でも小数欠落 | AD解釈/制限処理/保存経路を調査。書込みACKだけで保存成功としない |
| ARだけ整数、内部観測なし | 読戻しでの小数欠落は観測できるが、内部保存状態は未確定 |
| 再投入後だけ値/補正結果が変化 | 保持・読出し・係数再計算/反映の各経路を追加調査 |
| 異なる小数値なのにARが同じ | ARだけでは元値を一意に照合できない。整数化して照合OKにしない |

校正後測定値の差は入力変動・計器分解能・製品表示分解能・ADC生値の変化も合わせて評価し、変化が見えないだけで内部の小数消失と断定しない。許容誤差や合否閾値は設計仕様に従い、今回独自に設定しない。

AD_VERIFYの正式実装前は診断結果として記録する。ARが小数を失って一致判定不能な場合の正式応答は設計確認事項として残し、規定のOK/ERRを便宜的に割り当てない。製品の最終PASS/FAILはATEが判定する。

## 完了条件・記録先

3系統×2点について送信値→読戻しの対応を取得し、小数を保持する層/失う層/観測できない層を明示する。再投入後の保持と校正精度確認はそれぞれ別項目で結果を残す。未実施・未観測を成功扱いしない。

実施時は本案件の`docs/ADC_Decimal_Hardware_Test_<実施日>/run_<連番>/`へ、ケース一覧、個体/FW/source情報、送受信raw、測定/内部値、CSV/hash、結果/制限、復元記録を保存する。現時点では実機試験・FW変更・書込み・テスト実行なし。関連IssueはOpenを維持する。

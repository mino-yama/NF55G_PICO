# D2デバッグ時のPS_ON影響確認

確認日: 2026-11-07。対象: 現在のNF55G Pico試験治具案件。

## 確認できた事実

原典: `reference/RW11用電源通信仕様書r1.pdf`（GVT-284454-001-00）。

| 観点 | 確認内容 | 根拠 |
|---|---|---|
| PS_OFF中の受付 | D2は受付不可。受付不可の場合はシーケンスエラー。 | p.17 §7.1 |
| PS_ON後の受付 | SET CLOCK（SC）の処理完了までD2を受け付けない。 | p.17 注1 |
| SC未受信 | D2個別仕様でも、SET CLOCK受信前はシーケンスエラーを返すと明記。 | p.32 §10.6.1 |
| その他の受付条件 | GET DATA2行にはPS_OFF、RESTART中、SC受信前でシーケンスエラーの可能性が示される。 | p.18 §7.2 表 |
| 取得内容 | OFF期間データ30文字。T2は100ms。 | p.17、p.32 |
| データ更新 | OFF期間データはPS_OFF期間中に更新される。PS_ON中の継続更新を前提にしない。 | p.39 §13.5.1(1) |
| 時間分解能 | AC_OFF_HOUR、PS_OFF_HOUR、OFF_CHARGE_HOURは0.1時間（6分）単位。短時間比較では表示差が出ない可能性がある。丸め方法は今回確定していない。 | p.39 §13.5.2 |
| クリア条件 | D2後のSET LIFEでBATT_DEG以外をクリア。途中のAC OFFおよびPS_OFFについて例外条件がある。D2単独を即時クリアと解釈しない。 | p.32、p.39 |

Pico側の`src/command_dispatcher.py`の`execute_refresh`は、PS_ON Cacheを条件に送信を禁止せず、`D2_REFRESH`からD2を送る。SCの自動送信も行わない。`src/nf55_command.py`のD2定義はT2=100ms、応答DATA長30。

`PS_ON?`はSTATUS Cache参照のみである。現在状態の確認には先に`STATUS_REFRESH`の成功が必要。D2取得によってSTATUS Cacheは更新されない。

## デバッグ上の見立て（実機原因の確定ではない）

- `ERR:SQE`の場合: PS_OFF、PS_ON後のSC未完了、RESTART状態を優先して確認する。
- D2応答は正常だが値が変わらない場合: PS_ON中の更新を期待していないか、PS_OFF履歴・時間分解能・過去のSET LIFE実行を確認する。
- `ACK_TIMEOUT` / `RESP_TIMEOUT`の場合: PS_ONだけを原因と断定しない。仕様の受付不可時はシーケンスエラーのため、送受信フレーム、配線、電源、実FW動作を別途確認する。
- 確認順序の案: PS_ON状態確認 → NF55GへのSC処理完了確認 → 必要に応じSTATUS_REFRESHで状態再確認 → D2_REFRESH。Pico自身のRTC設定だけでNF55GへのSCを実施したことにはならない。
- 状態の切替えやSC送信、SET LIFE送信は今回実施していない。

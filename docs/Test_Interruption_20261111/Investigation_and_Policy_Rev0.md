# 試験中断・TEST_START再受信：混在調査と方針案

作成日: 2026-11-11 / Rev.0 / 状態: 基本方針採用・再STARTのソース修正とHost／Mock確認済み、修正版実機配置・正常系3試行確認済み。最新状態は第7節と実機結果。

案件保存先: `docs/Test_Interruption_20261111/`（ユーザー指定）。対象は作業ツリー上の現行ソース。実機へ配置されている版との一致は未確認。

## 1. 今回の要求と検討範囲

- ATE判断や製品特性による途中停止があり、TEST_ENDが届かない場合を扱う。
- Pico単独の周期Refresh、PS_ON?、通信可否確認で停止を推定しない。ATEからのTEST_START／TEST_ENDを管理の境界にする。
- 途中終了時のQR／シリアル、ログの混在を調べ、次のTEST_STARTで前回分を保全する処理を検討する。ソースには反映しない。
- TEST_END未受信という事実と、実際の中断理由・製品PASS/FAILを区別する。通信成功／失敗、PS_ON状態だけでは試験終了を断定しない。
- 2026-11-11ユーザー指定: 最重要要件は受付済みTEST_STARTごとに独立した試行IDを付け、1試行1CSVとすること。前試行と次試行を同じCSVへ追記しない。
- 製品の試験中には複数回のAC_OFFがある。製品電源の瞬断検出は要求せず、AC_OFFを試行終了・分割の根拠にしない。
- Pico 2自身の電源断時のデータ保持・復旧は要求しない。その際に試験途中のデータが消失することは許容する。ただし通常動作で次のTEST_STARTを受け付けた際の試行分離は必要であり、データ消失許容を試行混在の許容とは扱わない。

## 4. 採用する基本方針（2026-11-11ユーザー指定）

本節の基本方針を採用する。最重要要件は「受付済みTEST_STARTごとの独立した試行ID・1試行1CSV」。具体的なID生成方式、命名、受付応答等の詳細は引き続き設計対象とし、未実装である。

### 試行と製品の識別を分ける

TEST_STARTを受け付けるたびに独立した試行IDを付け、1試行1CSVとする。1回目、2回目、3回目を同じファイルへ追記しない。前試行がTEST_END未受信でも、次のTEST_STARTの受付で前試行と新試行を分離する。起動識別子＋試行番号等で区別し、同一秒でも衝突しない設計が必要。Pico再起動後に前試行を復旧・継続する必要はないが、既存CSVへの追記・上書きは防止する。ID生成方式は未確定。

TEST_STARTの回数だけでは「同じ製品の再試験」と「別製品への交換」を判別できない。QR末尾6桁だけも全製品を通じた一意識別とは未確定。QR原文と解析値を履歴として保存することと、次のSS書込みに利用できることを分離する。

### 状態遷移案

| 現在状態 | ATE指示 | 方針案 |
|---|---|---|
| 試験なし | TEST_START | 新試行開始。前回のQR・測定値を新規有効データとして採用しない |
| 試験中 | TEST_START | 前試行を「TEST_END未受信、次STARTによる区切り」として保全し、新試行へ切替え |
| 試験中 | TEST_END | 現試行を明示終了として保存。ATEのPASS/FAILは別情報 |
| 前試行保存中 | 後続操作 | 新試行へ誤記録・誤実行しないよう受付／実行を制御する |
| 試験なし | TEST_END | 新規CSVを作らず、重複終了の扱いを別途定義する |

「次STARTによる区切り」はPicoが中断理由や停止時刻を判定したという意味ではない。最後の処理時刻と次START受信時刻を記録し、実際の停止時刻は未確認として扱う。

### 切替え時に保全する情報

1. 前試行のID、開始時刻、最後の操作、QR原文／解析値、ログ用S/N、Cache取得履歴、保存異常・破棄件数を前試行に固定する。
2. 次START受信による区切り理由を前試行へ記録する。製品FAILやSS未実施を推定しない。
3. QR／DMMの旧要求を失効させ、遅れて到着した旧試行の応答を新試行へ採用しない。試行IDと要求IDを組み合わせる案。単なる受信バッファ消去だけに依存しない。
4. NF55G通信中はSDへアクセスしない。前試行のQueueと新試行のQueueの所有先を区別し、前試行の行を新ファイルに流さない。
5. 通信待機時に前試行を排出・flush・close・命名する。SD異常時は保存不能を明示し、保存成功を装わず次試行の記録と分離する。
6. 前試行の最終保存結果を次STARTで失わないよう、試行ID付きの履歴を持たせる。必要件数・永続化・ATE照会方法は未確定。
7. 新試行の書込み用QR資格を初期化する。製品Cacheも境界で全INVALIDにする案を推奨するが、現行仕様の変更であり承認後に反映する。自動Refreshはしない。

上記は論理順序であり、同期SD処理をすべて終えるまでATE応答を待たせる実装の決定ではない。切替えを受理した時点、ATEのOKの意味、保存中の後続コマンド、RAM上限と処理時間を設計する必要がある。NF55G Transactionを強制切断したり、並行実行したりしない。

### QR保持・SS書込み

- 2026-11-11ユーザー確定: 製品が変わったか識別できないため、QRを次試行へ引き継がない。同一製品の再試験でも例外を設けない。前試行のQR原文・解析値・S/Nは前試行の記録として保持する。
- 新しいTEST_STARTの受付時に、当該試行のQR・書込みシリアル・ログ用S/Nを未取得／無効にする。前試行で開始したQRの遅延完了も新試行の取得として採用しない。再試験では当該試行でQRを再取得し、ATEの明示指示で再度SSを実行する。
- SS実行要求時、当該試行の書込みシリアルが空ならPico側でエラーを返し、NF55GへSSを送信しない。前試行値・製品読出しCache・既定値で空を自動補完しない。エラーコードの正式名称、空の具体的判定（未取得・空文字・空白等）と書込み対象フィールドの対応は詳細設計で定める。文字列000000を空と同一視する等の値規則は今回確定しない。
- 新規QR取得、別QR受信、不正QR時の候補・確定値の扱いを決める。同一試行で別QRを受けてログ全体のS/Nを黙って差替える動作は避ける案。
- SSはATEの明示指示だけで実行する。中断・次START・TEST_ENDで自動書込み／自動再送しない。
- 将来SS実行中に応答を失った場合は「実行成否不明」として保存し、未書込みと断定しない。読戻しはATEの明示指示とし、OI-23のフィールド対応を推測しない。

### ファイル名案

例：`000001_20261111_101500_T000001.csv`、`000001_20261111_102000_T000002.csv`、未読時は`NOQR_20261111_102500_T000003.csv`。これは候補であり既存命名の確定事項を変更したものではない。起動をまたぐ一意性・再衝突時の処理は追加設計が必要。

CSV内にも試行ID・終了区分・QRとの対応を保存し、ファイル名だけに依存しない。命名を変える際はFileSDSinkの名前検査、容量集計、BANK循環削除の対象判定も同時に変更する必要がある。既存の循環保存方針による将来削除と、中断直後の保全は別問題として扱う。

## 5. 詳細設計で確認する事項

1. 受付済みTEST_STARTは2回目以降も毎回新試行とすることは確定。ATE応答喪失後の再送を同じ要求として識別する仕組みを設けるかは未確定。引数なしの同一文字列だけでは再送と新規開始を識別できず、再送も新たに受け付ければ別試行となる。
2. QRの次試行への引継ぎなし、再試験でのQR再取得・SS再実行、書込みシリアル空でのSS無送信エラーは確定。空の具体的判定・正式エラーコード、QRからSSへのフィールド対応と他の妥当性検証は未確定（OI-23）。
3. 最後の中断後に次STARTもTEST_ENDも来ない場合の保全範囲。周期flushで保存済みの行はあるが、S/N命名と終了区分は未確定のままになり得る。独立したATE中断指示を追加するか、次START待ちとするか。
4. 製品電源瞬断の検出とPico電源断時の途中データ保持・復旧は要求対象外と確定。電源断回復用の永続ジャーナルや未終了試行の自動復旧は今回の必須機能に含めない。既存CSVとの衝突回避は必要。
5. 切替え受付応答、保存中の扱い、同一秒の命名、複数試行の保存診断履歴、SD異常時の通知方法。

## 7. 再STARTの修正実施（2026-11-11）

ユーザーの修正開始指示により、前試行の排出・flush・close・命名→新試行開始を実装。新形式は日時＋T000001等の試行ID、当該試行のQR取得時はさらにS/Nを付加する。既存BANKの最大試行番号から採番し、同一秒・再mount後も既存ログへ追記しない。新試行のQR受信状態・S/N・全製品Cacheを失効する。

保存途中の通信で延期した場合は旧試行を保持してERR:BUSY、SD異常では旧試行の保存状態・破棄を保持して新試行を記録不能状態で受け付ける。再START間の自動再mountは行わない。直前完了試行の診断と最新8件のRAM履歴を保持する。詳細値・応答・残制約は[実装記録](Implementation_20261111.md)と正式Masterを参照し、第4節の候補記述より優先する。

Host／Mockは284件成功（従来273件＋新規11件）。修正版の実機配置・再START応答時間・新USB QR入力との結合は未確認。SS開発は保留。TEST-SESSION-01はOpen継続。

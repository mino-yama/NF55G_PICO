# RW11 改訂仕様書の治具開発と製品動作への影響確認

確認日: 2026-11-11　版: Rev.0　状態: 事前確認版に対するレビュー。設計回答待ち。

## 1 確認結果

通信r2はD0のT2を300msに統一し、D4とD5の長さの説明、D3のイベントロスト表記などを修正している。現行治具ではD0の600ms暫定値が変更候補となる。一方、D4=212文字、D5=100文字、SOCの符号付き変換などは既に実装と一致する。

購入仕様書はERP、充放電、保護、補正、QRの要求を具体化する資料として有用だが、通信r2と食い違う値や、同一文書内の不整合が残る。特にD4長、温度警告設定、QR容量・REV変換、補正条件、OFF期間の消去条件は、量産仕様へ取り込む前に設計確認が必要である。

今回、仕様基準・ソース・テストコード・実機配置は変更していない。AGENTS.mdのr1基準を維持し、既存OIをCloseしていない。新たに発見した矛盾と確認事項はOpen_Issues.mdへ記録する。

## 5 設計担当者への優先確認事項

### 5.1 D4の正式長と適用FW

確認事実: C2 p.27、32～33はTIME12＋REALTIME50＋DIAG30＋ACCUM70＋MFG50＝212。一方、P2 p.42はACCUM100、合計242。治具の期待長は212で、2026-11-09のD4試験記録にもDATA212の完全フレームが残る。

要確認: 量産FWの正式長・積算領域長・項目順をどちらに合わせるか。購入側の記載修正か、通信側への追加項目が必要か。C2の212採用でD4-TIM-01が解消するとは言えない。Picoで212／242を自動受理する変更は行わない。新規SPEC-R2-01。

### 5.2 温度警告と非送信フラグ

確認事実: C2 p.19のBBU_TEMP_THDは初期85℃、範囲60～95℃。P2 p.34の設定表は初期90℃、60～100℃、解除は閾値−10℃で、黄色表示。さらに同ページの保護表は検出90±5℃、解除75±5℃で、設定表の90−10=80℃と一致しない。ADUも保護表解除80±5℃と設定表85−10=75℃の関係が不明。FAN無効化はC2 p.19で65534rpmだがP2 p.34では254℃と記載。

要確認: 初期値・範囲・ヒステリシス、固定閾値と変更時閾値の関係、FAN無効化値の単位。C2 p.29のD1 ADU_TEMP_WNG欄は非送信、C2 p.16のEBおよびP2 p.34は同警告を列挙するため、D1のみ非送信なのかも明記を求める。保護設定を使った実機試験は確定後に別計画とする。新規SPEC-R2-02。

### 5.3 QRの容量条件

確認事実: P2 p.46はVersion 1、21セル、訂正M、内容35桁を同時指定。6項目の合計は8＋14＋3＋2＋2＋6＝35で、英字・ハイフンを含む。DENSO WAVEの[公式容量表](https://www.qrcode.com/en/about/versionPage/versionPage1_10.html)ではVersion 1／Mは数字34桁、英数字20文字、バイナリ14バイト、Version 2／Mは英数字38文字。

評価: Version 1／Mの最大の数字容量でも35桁に足りず、指定条件は両立しない。全35文字を大文字英数字モードで保持するならVersion 2／Mが容量上の候補だが、実際の文字種・生成方式・余白・印字寸法・読取りは別途確定する必要がある。

要確認: 版／セル数の訂正か内容構成の変更か。Picoの35文字受信を短縮して吸収しない。新規SPEC-R2-03、OI-23関連。

### 5.4 製品REVとQRからSSへの変換

確認事実: P2 p.5はQR列が「―」の一方、p.46はQR REV3桁を指定。p.5本文はA09以降の通信4桁目をピリオド固定とするが、表の例はA01.～A06.で、A09との適用関係が不明。ラベルREV表記もA1・等となる。C2 p.22はUNIT_REV4文字で、ADU／BBU個別管理なし・0応答と記載する一方、ADU_REVはユニットREV管理に従うとの記述も残る。

要確認: 実QR3桁の例、ラベルREV・QR REV・通信UNIT_REVの対応、A09の意味、ASCIIピリオド0x2Eを付ける対象と適用開始版。QR製造年／週からUNIT_LOTへの変換、号機とSERIAL、ADU／BBU9項目の書込み値・予約2文字・FW_REV欄の非更新表現も必要。P2 p.45のラベル製造年月YY_MMとQR製造週は別情報であり週から月を推測しない。

評価: 通信4文字目の記述はOI-23への回答候補だが、そのまま末尾ピリオドや全ゼロを補完するには不十分。SS実装保留・新試行QR非継承・空シリアル時無送信の方針を維持する。新規SPEC-R2-04。

### 5.5 補正条件とAD／ARの正式仕様

確認事実: P2 p.26本文はPS_OFF、最小負荷、バッテリ7.800±0.1Vの補正を説明。一方、同ページの三社電機方法はバッテリ電圧5V／10V・充電中・PS_ON無負荷の2点補正を示す。充電電流欄の2点は0.5V／1.85Vと電圧単位で、バッテリ電圧は＊＊、放電電流の2点は空欄。既存ユーザー要求は電圧8V／5V、充電電流1.85A／0.5A、放電電流44A／0.3A付近であり、実行状態は確認済みの組合せを保持している。

要確認: 採用する製造工程・補正点・単位・PS_ON状態・充放電状態・検出箇所・安定待ち・P1/P2対応。図中の方法はメーカー案なのか正式要求なのか。C2へAD／ARのフレーム仕様、TYPE対応、VALUE／REF表現、PME、保存・即時反映・再起動要否、T2、応答長を追補するか。

評価: 7355取得とATE判定後の明示書込みを分ける既存要求は維持する。測定値をPicoで自動採用・書込みしない。新規SPEC-R2-05、CAL-EXT-01とOI-04／05／12／16～21関連。

### 5.6 OFF期間とSLの消去条件

確認事実: C2 p.39とP2 p.38はD2後のSLで情報をクリアとするが、C2 p.32はBATT1,2_DEG以外を消去、途中のAC OFFおよびPS_OFFで消去しない例外を残す。C2 p.23はGET DATA後という広い表現。C2 p.39からは例外記載が削除されており、同じ版の中で一致しない。

要確認: D0とD2のどちらが消去を許可するか、GET DATA3との関係、途中の電源／PS状態変化、消去タイミングと対象、劣化度を残す範囲。AC_OFFの時刻差計算もSC補正・時計逆行時の扱いが未記載。過去のSL通常値試験でOFF欄が変わったことだけで全条件を確定しない。新規SPEC-R2-06、OI-08関連。

### 5.7 多重受信とACKの終結条件

確認事実: C2 p.7は先行処理継続と最終ACK正常受信までのシーケンスを明記。一方p.11の多重図は最後がレスポンス②とACK①で対応が不明。p.14の装置側図ではコマンドACK受信後もT1スタートと表示されるが、p.8本文と現行実装は応答待ちT2を使う。

要確認: 多重時にMCMがどちらのCMD IDで返り、先行応答がどの順で継続するか。ACK欠落・遅延応答・再送コマンドが重なる場合の正式な終結と再受付、図の番号／タイマー名を確認する。既存OI-11のEB競合試験、D4-TIM-01の遅延応答評価と併せて確認する。新規SPEC-R2-07。Pico側T1=200msの正式回答は依然不足する。

### 5.8 充電禁止解除とCacheへの影響

確認事実: P2 p.21はCFでAUTO_CHARGEを無効にし、クリア後は受信前の設定へ戻ると記載。C2 p.25はCF DATA=0で充電禁止解除とする。P2 p.36はバッテリラッチ解除にCLEAR DATA・特定の再起動・交換を挙げ、p.37の一覧はAC／PS_ON操作を×とするため、交換フローを含む条件付き操作と単独操作の区別が必要。

要確認: CF中のD5 AUTO_CHARGEは元の保存値か、実効値0か。クリアはCF DATA=0かCDか、双方か。CDの0／1／2ごとのラッチ・満充電情報・計数値の消去範囲を明記する。既存ATE-CLEAR-01のCLEAR_DATA名称対応とは別問題である。

実装への見立て: 現行CFはDATA／STATUSだけ、SLはDATAだけ、CDはDATA／STATUS／BCを失効する。INFOやD2／D3／D4を追加失効すべきかは、保存した過去スナップショットをVALIDのまま参照させる契約と合わせて設計確認が必要。現行Cache Masterがその規則を明記しているため、今回独断で対象を変更しない。新規SPEC-R2-08。

### 5.9 瞬断回数と低電力の観測条件

確認事実: P2 p.11は停電検出85V以下、設計値75～83V、PS_ON時のみ・1秒内の繰返しは1回とする。一方P2 p.38とC2 p.41のAC_FAIL_COUNT名は70V以下。P2 p.11の短時間瞬断・変動の動作規定はバックアップへ切り替わらないとしつつ、一時的バックアップの可能性・放電なしの注記もある。C2 p.29のBURST_ONはBURST状態、p.30では入力信号に依存・実バーストに非依存とする。

要確認: AC_FAIL_COUNTの正式検出閾値・瞬断と瞬低の分類、復電判定、放電開始とバックアップ通知の区別、BURST_ONが表す観測対象。ATEの波形・計数・消費電力期待値を定める前に回答が必要。新規SPEC-R2-09、ERP-CONDITION-01関連。

## 7 確定後に行う変更と試験の案

1. r2正式採用範囲・適用製品FW／HWを確認し、AGENTS.md／READMEと各Masterの基準を同期する。原典PDFは変更しない。
2. D0のT2を300msへ変更する場合、src/config.pyと関連日本語コメント、Protocol仕様、OI-02、CHANGELOG、Host／Mockを同時更新する。応答が境界直前／直後になるケース、EB介在でも元deadlineを延長しないこと、timeout時のcommand retry上限1とambiguous／Cache失効を確認する。
3. D4／D5／EL／OL／D3は確定長・IDを固定し、不正長を部分採用しない。212／242の自動切替は正式要求なしに追加しない。
4. QRは承認された実印字Sampleで35文字・先頭ゼロ・REV・年／週・S/Nを確認する。試行ID／要求ID、切断・再読取・遅延完了・空シリアル時無送信を検証し、SSは正式対応表が確定してから実装する。
5. ERP／BE／BC／SL／CD／CF／ORは通信成功と外部動作を分け、元設定退避→明示操作→明示Refresh→外部計測→復元の手順を対象ごとに定める。SLやCDの消去済みデータは設定書戻しだけでは復元できない。
6. AD／ARは7355取得だけでは書込まないこと、ATE指定数値を使うこと、補正対象・点・測定条件が対応すること、保存と即時反映・再起動要否を確認する。

# ADC並行開発・後続QR連携計画 Rev.0

作成: 2026-11-22。案件: NF55G Pico試験治具。

## 今回の指示と実施順序

ユーザー指示により、現在の先行デバッグと並行してADCの実装準備・独立部分の開発を進め、先行デバッグ後に統合する。その後、実データが確定したQRについて、読取り・Cache・書込み先までATEから制御する仕様を検討する。日程の自動実行や実機書込みの実施を意味しない。

1. 先行デバッグ: HOST通常RST、USB IN切分け、QR取付け後の単独入力確認、前提成立後の共存確認を既存[23日計画](Debug_Development_Plan_20261123_Rev0.md)に従って進める。
2. ADC並行開発: 保存済みの校正仕様と既存Cache基盤を利用し、測定取得から書込み・個別照合までの接続を小単位に分けて準備する。診断中のmain/dispatcher/linkへ未検証の変更を統合しない。
3. ADC統合: 先行デバッグの基準版と結果を保存後、ADC追加版でHost Unit/Mock・関連実機・共存を順に確認する。先行デバッグ後でも正式通信契約に未回答がある機能は送信可能にしない。
4. QR連携検討: ADC統合に続き、確定した実データを基にATE操作・Cache・書込み先の契約を具体化する。先行するQR単独確認はこの正式連携の完了を意味しない。

旧23日計画のHOLD-02は「ADC全体の準備を止める」の意味ではなく、未確定のAD/AR契約に依存する送信・照合を保留するものとして扱う。

## ADCの開発単位と受入

2026-11-22追加ユーザー指示: NF55G製品FWの小数扱いを実機検証する。[小数切分け試験計画](ADC_Decimal_Hardware_Test_Plan_20261122_Rev0.md)をADC統合後の受入へ追加。AD送信/内部保存/AR出力/補正測定を分け、電源再投入前後も確認する。今回計画のみ。

| 単位 | 接続する処理 | 検証内容・統合条件 |
|---|---|---|
| ADC-1 | ATEの明示測定要求→外部測定器→完成応答検証→測定Cache | 対象/点/試行/取得を照合。機器応答の単位とオーバーレンジをadapterで確認。任意の数字応答を自動採用しない |
| ADC-2 | Cache照会→ATEへ原文・数値・単位・識別情報を返す | Queryで測定/NF送信なし。再取得失敗後の旧値復活なし。TEST_START/ENDで前試行を除外 |
| ADC-3 | ATE採用後の別指令→指定Cacheまたは数値直接指定→AD | A/BとP1/P2、TYPE/VALUE8、極性/丸め、応答/T2、失効規則を仕様照合後に実装。自動再測定なし |
| ADC-4 | ATEが対象/Point指定→AR個別照合→ログ/応答 | 同一試行・対象・点の直前正常書込みと比較。小数を保持する正式読戻し契約が必要 |
| ADC-5 | ADC追加版の実機・共存受入 | 単独で取得/照会/書込み/照合を分離確認後、ATE/NF/SD/RTCと共存。製品PASS/FAILはATE |

ADC-4の要求応答は`OK:AD_VERIFY`、`ERR:AD_VERIFY_MISMATCH`、`ERR:AD_VERIFY_TIMEOUT`。それ以外の失敗応答や正式引数は未確定。レビュー済み製品FWのAR整数化で小数を失う問題は既存記録を継承し、治具の丸めで一致にしない。

正式API確定時はATE_Command_Master/Cache_Master/Software_Module_Interface/Test_Specification/Open_Issues/CHANGELOGとCode/Testを同時更新する。実機の基準ソース・UF2を保存し、ADC追加版の配置と回帰は先行デバッグ後に行う。

## QRのATE制御案（正式API未確定）

| ATE操作 | 役割 | 保持/照合する内容 |
|---|---|---|
| 読取開始・取消 | 現試行の受信受付を開始/取消 | 試行世代・要求ID・期限。リーダへの遠隔トリガとは区別 |
| 原文/解析Cache照会 | 確定実データを原文と6項目で返す | 先頭ゼロ/大小文字、受信完了、要求識別。照会だけでは再読取しない |
| 書込み先/値の確認 | ATEがCacheの項目とNF55G書込み対象を明示する案 | 使用Cacheの識別、対応規則、生成する書込み値を事前に確認可能にする |
| 明示書込み | ATEが確認したCacheと対象だけを使用 | 現試行/最新取得/変換規則を照合。INVALIDや空シリアルではNF送信しない |
| 明示読戻し・照合 | 必要時に書込み値を確認 | 書込み対象・読戻し要求と結果を相関。製品判定はATE |

書込み先は任意アドレスではなく、通信仕様とユーザー指定に基づくSS対象項目として検討する。既存候補はUNIT/ADU/BBUそれぞれREV/LOT/SERIALの9項目。正式なコマンド名・引数・応答・部分書込み方法はこの計画で確定しない。

QR実データが確定したことと、全項目の書込み変換規則が確定したことは分ける。確認が必要な事項は、REV3→UNIT_REV4の格納規則、年/週とLOTの対応、号機とUNIT_SERIALの対応、ADU/BBUの取得元、SSの50文字内配置/予約領域/部分更新方法。品名/品目コードの書込み先は未指定。確定済みのログ名用末尾6桁をSS変換の根拠にしない。

読取開始前・前試行・取消後の残留/遅着、不正長/文字、断片/期限切れの後の正常入力を検証する。Cache照会・読取だけでSSを送信せず、書込み時にも再読取しない。SS後のDATA/INFO失効と明示Refreshの規則を維持する。

## 今回の作業結果と残事項

今回実施したのは関連仕様/既存コードの確認と本計画・引継ぎの更新。新規コード実装、テスト再実行、FW build/配置、実機送信は行っていない。文書差分の空白検査を行う。基盤実装済みと一連機能完成を区別する。

AD/AR正式契約・AR小数読戻し、QR実データの出典/版とSS変換規則が継続確認事項。関連Open IssuesはCloseしない。本計画を理由に既存の製品FW差異を治具側で吸収しない。
